# 确认

产品自动任务以本轮提示词给出的可信 helper 完整命令替代下列 `python3` 示例；不得执行 staging 内的工具副本。

1. 先运行 `python3 tools/wiki_session.py --root . status`，确认本 Agent 从包装器启动且共享写锁覆盖整个编辑窗口；失败就停止写入，不能只看环境变量。再完整读一遍 `AGENTS.md`（尤其第 7.1、7.7、7.8 节）。
2. 运行 `python3 tools/kb.py`，把最新的 `wiki/待确认.md` 原样展示给用户，逐条带编号。末尾最多顺带一个与当前内容相关的问题。
3. 等用户回复，例如"1、2 对，3 改成……，4 不对"。**用户没有回复的条目保持候选，不催促，不替用户决定。** 整段确认回复只是操作指令，包括“改成……”原话和理由在内，一律不另存为 `raw/自述/`。
4. 按 7.8 处理：
   - **对**：新页面的 `确认` 改为 `已确认`，其"演化"里对应记录的状态也改为 `已确认`；修订用候选记录的内容更新"当前判断/当前做法"；候选链接删去行末"（候选）"。
   - **改成……**：按用户原话修改后，按"对"处理。
   - **不对**：删除该候选页面、候选演化记录或候选链接行，在 log.md 记下被否决的内容和原因。
5. 在 `wiki/log.md` 追加一条 `confirm` 记录（如"3 对、1 改、1 否"），运行 `python3 tools/kb.py`，确认错误为 0。
6. 如果待处理素材与待确认事项都已清零，并且尚未做过完整体检或上次体检后有变更，按 AGENTS.md 7.6 直接继续完成体检。

确认过程中保留 `kd-wiki-display` 展示块和产品展示 class，不手改其中的状态文案；运行 `tools/kb.py` 后由脚本刷新。
