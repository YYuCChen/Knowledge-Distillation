# 个人知识库维护规则

> 本文件是维护本知识库的 AI 必须遵守的规则，与具体模型无关。每次开始工作前完整读一遍。
> Codex 等工具读取 `AGENTS.md`；Claude Code 读取 `CLAUDE.md`；其他工具请在其系统提示中引用本文件。
> 本文件依据《个人知识系统方案骨架》编写，两者冲突时以方案文档为准，并提醒用户修订本文件。

---

## 0. 十条铁律（任何情况下不得违反）

1. **原始素材只读。** `raw/` 下的任何文件永不修改、移动或删除。
2. **单向派生。** 素材 → wiki → 关系图谱。永远不从图谱反推修改 wiki，不从 wiki 反推修改素材。
3. **他人与自己分开。** 他人观点一律写成"某某认为……"。外部素材永远不直接生成认知页。"用户怎么看"只能来自 `raw/自述/`。
4. **不替用户下结论。** 认知页、方法页、实践记录、技能、触发源关联、反例，只能以"候选"状态提出，用户确认后才转正。
5. **出处链。** 每个论断都能追溯到页面或原始素材；追溯不到的，标为 `[推测]`。
6. **标题永不修改。** 标题是页面身份，链接指向标题。
7. **不写脚本生成的内容。** 带 `（自动）` 的小节、index.md、待确认.md 只由脚本 `tools/kb.py` 生成，你不手写、不手改。
8. **综合页不作依据。** 综合页是派生内容，不得出现在其他页面的"依据"或"事实依据"中。
9. **状态靠计算。** 已下透、悬空、消化状态、实践次数等由脚本计算，不写入页面。
10. **页面不截断。** 读页面时要么完整读入，要么不读。

## 1. 目标与读者

**目标：** 让外部信息经过消化转化为用户自己的认知，再下透为方法和技能，落地为行动，并由现实反馈回头修正。

**衡量标准：** 不是收录了多少，而是认知是否改变了用户做事的方式。

**读者：**
- 主要读者是 AI（你）。结构、格式、命名都以 AI 好读、好查、好解析为先。
- 用户也会阅读和手动编辑页面，所以正文必须是通顺的中文。

**知识的两个坐标：**
- 主题（关于什么）：商业、生意经、社科、人情世故、AI、投资、健康。共七个，新增主题需修订本文件和脚本。
- 类型（哪种知识）：认知（怎么看）、方法（一般怎么做）、技能（具体怎么做）。

## 2. 目录结构

```
raw/                      原始素材，只读
  外部/                   人工核查后的外部整理稿（社媒、博客、书籍等）
  自述/                   用户的文字或语音片段；AI 对话中用户本人的发言
  数据/                   结构化数据（流水、账单、体检等），用户手动上传

wiki/
  来源/  概念/  认知/  方法/  技能/  实践/  综合/  主题/     由你编写
  log.md                  变更日志，由你和脚本追加
  体检报告.md             每周检查报告，由你编写
  index.md                总索引，脚本生成
  待确认.md               待确认清单，脚本生成

skills/                   技能的 Skill 文件
tools/kb.py               检查与关系图谱脚本
.graph/                   派生数据，可随时删除重建
  graph.json              关系图谱（节点、带类型的边、演化事件、计算状态）
  检查结果.md             脚本每次运行的检查结果
  state.json              脚本内部状态
  queries.jsonl           查询覆盖记录，由你追加
```

- 按**类型**分文件夹，主题只作标签，不建主题文件夹。
- 文件名即标题，扩展名 `.md`。

## 3. 页面类型与模板

### 3.1 八类页面

| 类型 | 回答的问题 | 编号前缀 | 知识归属 | 写入权限 |
|---|---|---|---|---|
| 来源页 | 这份素材讲了什么 | SRC | 他人 | 直接写 |
| 概念页 | 这个东西是什么 | CPT | 他人 | 直接写 |
| 认知页 | 用户怎么看 | C | 用户 | 候选，需确认 |
| 方法页 | 一般该怎么做 | M | 用户 | 候选，需确认 |
| 技能页 | 具体怎么做 | SKL | 用户 | 候选，需确认 |
| 实践记录页 | 做了什么，结果如何 | P | 事实 | 候选，需确认 |
| 综合页 | 某次提问得出了什么 | SYN | 派生 | 用户同意后写 |
| 主题页 | 这个主题下有什么 | T | 汇总 | 只写"概览" |

### 3.2 标题规则

- 认知页、方法页：**以问题命名，不以答案命名。**
  - 对：`谈判中面子的作用`、`合作谈判的开局顺序`
  - 错：`面子是谈判里的隐性筹码`、`先让利再谈条件`
- 概念页：名词本身，如 `谈判`、`注意力机制`。
- 来源页：`来源：` + 素材标题，如 `来源：影响力`。
- 实践记录页：`年-月 + 事件`，如 `2026-10 与某客户的合作谈判`。
- 技能页：任务名，如 `谈判前准备`。
- 综合页：`综合：` + 问题的简短表述。
- 主题页：主题名，已由脚本初始化，不新建。
- 标题不得含 `\ / : * ? " < > |`；冒号一律用全角"："。
- **同一个问题只能有一页。** 新建前先查索引；若已有页面在回答同一个问题，更新它而不是新建。
- 用户的看法分裂成两个不同判断时，拆成两个更细的问题，各自一页。

### 3.3 小节标题是结构的一部分

各模板中的二级标题（`## …`）决定链接的关系类型（见第 5 节），**必须一字不差**，不得增删、改名、调换含义。
标有 `（自动）` 的小节由脚本生成。新建页面时照样写上这些标题，内容留空即可。

### 3.4 模板

新建页面时，`编号`、`类型`、`创建`、`更新` 四个字段**可以不写**，脚本会补填。以下模板中省略了它们。

**认知页**

```markdown
---

当前判断: 面子是谈判里的隐性筹码
确认: 候选
证据: 有据

## 当前看法
一两段话说清楚观点。

## 依据
- 来自片段：raw/自述/2026-10-12.md
- 来自素材：[[来源：某书]]
- 来自经历：[[2026-10 与某客户的合作谈判]]

## 演化
- 2026-10-12 | 形成 | 面子是谈判里的隐性筹码 | 起因：raw/自述/2026-10-12.md | 候选

## 推论到做法（自动）

## 相关概念
[[谈判]]、[[面子]]
```


## 4. 写作规则

1. **语言：** 中文，简洁、通顺。
2. **他人与自己：**
   - 来源页、概念页中，他人观点一律写成"某某认为……"并链接来源。
   - 认知页只写用户的观点，"依据"中必须至少有一条 `raw/自述/` 路径或一条已确认的实践记录。
   - 仅有外部素材支持、没有用户片段支持的观点，**不得**写成认知页。
3. **出处：** 每个事实性论断后附链接，指向来源页、实践记录页或原始文件路径。
4. **证据等级：** 页面级写在元数据 `证据` 字段：
   - `推测`：没有直接依据，或由你推断而来
   - `有据`：有原始素材或用户片段支持
   - `已验证`：有已确认的实践记录支持
5. **段落级推测：** 页面中个别推测性段落，段首加 `[推测]`。
6. **从严主题：** 投资、健康两个主题下，每个论断都必须有出处；不得出现未标注的推测。
7. **单页长度：** 正文不超过约 1500 字。超出时按更细的问题拆页。
8. **有条件的知识：** 方法页必须填写"适用条件"与"不适用条件"；一时写不出，写"待补充"。
9. **世界时间：** 只对有时效的事实标注有效期，主要是 AI、投资主题的概念页：
   ```
   - 某公司的 CEO 是某某（有效期：2024 至今；记录于 2026-09；来源 [[来源：某报道]]）
   ```
10. **演化记录：** 认知页、方法页的每次形成或修订，在"演化"小节追加一行，格式固定：
    ```
    - 日期 | 形成/修正 | 新的判断或做法 | 起因：链接或文件路径 | 候选/已确认
    ```
    旧的记录永不删除。

## 5. 链接规则

### 5.1 链接语法

使用 `[[标题]]`。链接原始文件时直接写路径，如 `raw/自述/2026-10-12.md`。

### 5.2 关系类型由所在小节决定

链接写在哪个小节，就是哪种关系。不引入任何特殊语法。

| 小节 | 关系 | 方向 |
|---|---|---|
| 认知页 · 依据 | 依据 | 认知 → 来源 / 实践 / 片段 |
| 认知页 · 相关概念 | 相关 | 认知 → 概念 |
| 方法页 · 来自认知 | 来自 | 方法 → 认知 |
| 方法页 · 不适用条件 | 反例 | 来源 / 实践 → 方法 |
| 技能页 · 来自方法 | 落地为 | 技能 → 方法 |
| 实践记录页 · 做了什么 | 实践了 | 实践 → 方法 / 技能 |
| 实践记录页 · 影响 | 修正 | 实践 → 认知 / 方法 |
| 实践记录页 · 事实依据 | 依据 | 实践 → 片段 / 数据 |
| 来源页 · 引发的想法 | 触发 | 来源 → 认知 |
| 概念页 · 相关概念 | 相关 | 概念 → 概念 |
| 综合页 · 依据 | 依据 | 综合 → 页面 / 片段 |
| 其他任何位置 | 提及 | 任意 → 任意 |

"演化"小节中的链接不构成关系，作为演化事件的起因记录。关系类型是封闭集合，新增类型需修订本文件和脚本。

### 5.3 只存一个方向

- **向上的链接由你填写：** 方法写明来自哪个认知；技能写明来自哪个方法；实践记录写明用了哪个方法。
- **向下的链接由脚本生成：**

| 自动小节 | 来源关系 |
|---|---|
| 认知页 · 推论到做法 | 方法页"来自认知" |
| 方法页 · 落地为技能 | 技能页"来自方法" |
| 方法页 · 实践记录 | 实践记录页"做了什么" |
| 技能页 · 使用记录 | 实践记录页"做了什么" |
| 概念页 · 我的相关认知 | 认知页"相关概念" |
| 主题页 · 核心认知 / 核心方法 / 常用概念 / 状况 | 各页元数据与链接 |

要改自动小节的内容，就去改另一端，然后运行脚本。

### 5.4 候选链接

触发源关联和反例是单条链接，不是整页，用行末标记表示候选：

```markdown
## 引发的想法
- [[谈判中面子的作用]]（候选）
```

用户确认后删去"（候选）"；否决则删除整行。脚本会把带标记的链接汇总进待确认清单。

## 6. 元数据规范

| 字段 | 谁来写 |
|---|---|
| 编号、类型、创建、更新 | 脚本补填。新建页面时可以不写；已有的不要改 |
| 确认 | 新建时你写 `候选`；用户确认后你改为 `已确认`（见 7.8） |
| 主题、当前判断 / 当前做法、证据，及各类型专属字段 | 你；用户发现错误时可直接改 |
| 已下透 / 悬空、消化状态、实践次数、最近实践时间 | 不写入页面，由脚本计算，见 index.md 与 graph.json |

- 元数据使用 YAML frontmatter，字段名使用本文件中的中文名，一字不差。
- 列表写成 `[甲, 乙]`；日期写成 `年-月-日`。
- `主题` 只能取第 1 节列出的七个值。
- `确认` 只能取 `候选` 或 `已确认`。
- `证据` 只能取 `推测`、`有据`、`已验证`。
- 其他枚举值见模板中的注释。

**脚本的计算规则：**
- 已下透：已确认的认知页被至少一个**已确认**方法页的"来自认知"链接；否则为悬空。悬空只作信息展示，不是待办，不催促用户。
- 外部素材 / 自述片段已处理：被任何页面引用，或在 log.md 中出现过路径；否则为待处理。
- 实践次数：方法页或技能页被多少条已确认实践记录的"做了什么"链接。

## 7. 操作流程

### 7.1 权限表

| 类别 | 内容 | 你的权限 |
|---|---|---|
| 永不修改 | `raw/` 下全部文件 | 只读 |
| 直接修改 | 来源页、概念页、主题页"概览"、log.md、体检报告.md | 修改后记日志 |
| 候选待确认 | 认知页、方法页、实践记录、技能、触发源关联、反例 | 只能以候选状态写入 |
| 用户同意后写 | 综合页 | 用户明确同意才创建 |
| 不碰 | 自动小节、index.md、待确认.md、`.graph/` 下除 queries.jsonl 外的文件 | 由脚本生成 |

一句话：**涉及"别人说了什么"，可以直接写；涉及"用户怎么想、用户做了什么"，只能提议。**

**候选的写法：**
- 新建的认知页、方法页、技能页、实践记录页：直接创建文件，`确认: 候选`。
- 对已确认的认知页或方法页的修订：不改"当前判断/当前做法"，只在"演化"末尾追加一行状态为 `候选` 的记录。
- 触发源关联、反例：按 5.4 写带"（候选）"标记的链接。
- 你不需要手写待确认清单，脚本会从以上内容自动汇总。

### 7.2 ingest：外部素材

1. 运行 `python tools/kb.py`，查看 `.graph/检查结果.md` 的"待处理素材 · 外部"。
2. 为每份新素材建来源页：摘要；核心论点一律写成"作者认为……"。
3. 更新相关概念页：把新观点加入"各家观点"；时效事实标注有效期；没有对应概念页且该概念重要时，新建概念页。
4. **写入时检查冲突：**
   - 与他人观点冲突：在概念页"各家观点"中并列，不选边。
   - 与用户的**方法**冲突：在该方法页"不适用条件"中加一行指向来源页的链接，行末加"（候选）"。
   - 与用户的**认知**冲突：在该认知页"演化"末尾追加一行候选修订，起因写该来源页。
   - 两种情况都不改动"当前判断/当前做法"。
5. 在 log.md 追加记录，运行 `python tools/kb.py`，按 7.5 处理检查结果。

**外部素材永远不直接生成认知页。**

### 7.3 ingest：个人片段

1. 运行 `python tools/kb.py`，查看"待处理素材 · 自述"。
2. 判断类型：**想法**、**反馈**，或**都不是**（如待办、闲聊）。都不是的，在 log.md 记一行"跳过：路径（原因）"，脚本就不会再列为待处理。
3. **想法：**
   - 全新的看法 → 新建认知页，`确认: 候选`。
   - 印证已有看法 → 直接在该认知页"依据"中补充这条片段（只补证据，不改观点，无需确认）。
   - 改变已有看法 → 在"演化"中追加候选记录。
   - 同时按 8.3 寻找触发源，在对应来源页"引发的想法"中写候选链接。
4. **反馈：**
   - 推测关联的方法或技能，新建实践记录页，`确认: 候选`，写明结果。
   - 结果与方法预期相反时，同时在方法页"演化"中追加一条候选修订。
5. 在 log.md 追加记录，运行 `python tools/kb.py`，按 7.5 处理检查结果。

**AI 对话中的发言：** 只把**用户本人说的话**保存到 `raw/自述/`（文件名 `日期-对话.md`），AI 的发言不保存。之后与普通片段走相同流程。

### 7.4 query：用户提问

1. 先读 index.md，挑出相关页面。
2. 按第 8 节沿链接扩散，读取相关页面全文。
3. 作答时区分三种来源，并在引用处标明：
   - 用户已确认的观点
   - 仍为候选的观点
   - 他人的观点
4. 每个论断附出处链接。
5. 回答有保存价值时，在末尾用一句话提议保存；**用户同意才**创建综合页。
6. 在 `.graph/queries.jsonl` 追加一行 JSON：`{"日期": "2026-10-01", "页面": ["标题1", "标题2"]}`（不记问题原文）。
7. **搭车提问**（见 7.7）。

### 7.5 程序检查（每次写入之后）

运行：

```
python tools/kb.py            # 完整运行（Windows 用 python，macOS/Linux 可能是 python3）
python tools/kb.py --dry-run  # 只检查，不修改文件
```

脚本会补填程序字段、生成关系图谱、重写自动内容、生成 index.md 和待确认.md，并把检查结果写入 `.graph/检查结果.md`。退出码为 1 表示存在"错误"级问题。

处理结果：
- **错误**：必须修复，然后再运行一次，直到没有错误。
- **提醒**：能修的修；修不了或需要用户判断的，记入下次体检报告。
- **信息**：只供每周检查参考，不需要处理。

### 7.6 AI 检查（每周）

先运行脚本，以 `.graph/检查结果.md` 为基础，再做脚本做不到的判断：

1. **矛盾：** 找出页面之间相互矛盾的论断。每条发现必须附**双方原文引用**；引用须能在对应页面中逐字找到，找不到的发现一律丢弃。需要用户判断的，按 7.1 的候选写法写入。
2. **过时：** AI、投资主题中有效期内的事实，距上次复查超过 3 个月的，重新核对。
3. **下透情况：** 汇总检查结果中的悬空认知（仅列出）、未实践的方法、长期不用的技能、被推翻未修正的方法。
4. **盲区：** 主题页"状况"中只有外部观点的概念；检查结果中从未被查询读取过的页面。
5. 重写各主题页"概览"。
6. 写 `体检报告.md`（格式见 9.3），在 log.md 追加记录。

### 7.7 搭车提问

需要用户提供信息时（如某方法最近是否用过、效果如何），**不单独打扰用户**，只在以下时刻顺带问：
- 用户提问时，附在回答末尾
- 用户打开待确认清单时，附在清单最后

规则：
- 每次对话最多一个问题。
- 必须与当前话题相关；没有相关的就不问。
- 用户不回答，不追问，下次不重复同一问题。
- 问法要轻，一句话能答。
- 用户的回答会作为片段读入，生成实践记录候选，无需额外操作。

示例：
> 顺便问一下：你之前记过"合作谈判的开局顺序"，最近有机会用上吗？

### 7.8 confirm：处理待确认清单（用户发起）

1. 先运行脚本，把最新的 `wiki/待确认.md` 展示给用户。
2. 用户在对话中回复，如"1、2 对，3 改成……，4 不对"。
3. **对：**
   - 新页面：`确认` 改为 `已确认`，其"演化"中对应记录的状态也改为 `已确认`。
   - 修订：用候选记录的内容更新"当前判断/当前做法"，该演化记录状态改为 `已确认`。
   - 候选链接：删去行末"（候选）"。
4. **改成……：** 按用户的原话修改后，按"对"处理。
5. **不对：** 删除该候选页面、候选演化记录或候选链接行；在 log.md 记录被否决的内容与原因。
6. 未回复的条目保持候选，不催促。
7. 在 log.md 追加记录，运行脚本。

### 7.9 领域技能的产生

检查结果或索引显示某个方法有 3 条以上"有效"的已确认实践记录、做法已经稳定时，提议将其封装为技能：
1. 新建技能页，`确认: 候选`，"来自方法"链接到该方法；在"用途"中写明技能名称和内容要点。
2. 用户确认后，在 `skills/技能名/SKILL.md` 写入可直接执行的清单、模板或步骤。

### 7.10 陪读模式

用户说"陪我读这一篇"时，改为逐篇读入：先与用户讨论要点，再按 7.2 写入。讨论中用户本人的发言按 7.3 保存为片段。

## 8. 检索规则

### 8.1 三步检索
1. **读索引：** index.md 一次读完，按标题和当前判断挑出相关页面。
2. **沿链接扩散：** 从挑出的页面出发，最多走两步。需要时可读 `.graph/graph.json` 查找带类型的关系。优先走依据、来自、落地为、实践了、修正、反例；最后才走提及。
3. **关键词补充：** 人名、机构名、数字等精确信息，用全文逐字匹配搜索 `wiki/` 与 `raw/`。

### 8.2 上下文
- 常驻：本文件、index.md。
- 按需：检索到的页面；只在核对原文时读 `raw/`。

### 8.3 寻找触发源
新想法进来时，用同样的方法在来源页和原始素材中找出最可能引发它的至多 3 份，按 5.4 写成候选链接。找不到时，只链接到主题。

## 9. 系统页格式

### 9.1 index.md 与 待确认.md

由脚本生成，格式以脚本输出为准，你不手写。

### 9.2 log.md

只追加，不修改。每条以固定前缀开头：

```markdown
## [2026-10-01] ingest | 来源：影响力
- 新建：[[来源：影响力]]
- 更新：[[谈判]]、[[互惠]]
- 候选：反例 1 条

## [2026-10-01] ingest | 自述片段
- 跳过：raw/自述/2026-10-19.md（待办）

## [2026-10-07] lint | 每周检查
## [2026-10-08] confirm | 3 对、1 改、1 否
```

脚本每次修改文件后，也会自动追加一条 `check | 程序检查`。

### 9.3 体检报告.md

```markdown
# 体检报告 2026-10-07

## 已自动修复
## 需要你决定（已以候选方式写入，见待确认清单）
## 矛盾（附双方原文）
## 可能过时
## 下透情况
- 悬空认知：……（仅供参考）
- 未实践的方法：……
## 盲区
```
