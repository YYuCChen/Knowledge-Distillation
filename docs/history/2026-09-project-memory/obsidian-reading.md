# Obsidian 内容结构与阅读样式：阶段结论

2026-09-08。用户最后意见：“就先这样吧”。含义：当前预览暂告一段落，保留作为下一版本依据；不代表批准正式发布、迁移旧笔记、删除媒体或全产品验收。

## 目标场景与确认方向
- Local Web 偏流式轻读；Obsidian 偏定位后的细读、核查证据。优化既有蒸馏结果，不另生成一篇分析文章。
- 已有副标题、摘要、观点、论证、完整证据和来源正文可复用；本样稿不新增 AI 分析字段或调用。OCR 碎屑整理是独立缺口，并不存在已保存但未展示的干净阅读稿。
- 沿用 AnuPpuccin，加本地可关闭的 CSS。拒绝奶色、低对比目录、彩色引用大块和圆角观点卡片；中性白灰、深灰文字、低饱和链接。
- 640px 居中主栏，主体统一左对齐；思源宋体参考现有 Local Web，17px 正文、主标题/观点较重；编号悬挂对齐。依据 15px、较紧行段距，作为次级阅读，不与主干同权重。
- 来源信息两列两行：左为平台、博主；右为原帖入口、素材发表时间。只显示信息值，不显示“来源平台/博主/发表于/北京时间”等说明标签。底层保留时区，不能以蒸馏时间冒充发表时间。
- 顶部概览/观点与依据/来源全文定位入口；章节和相邻观点以留白、细线分隔。
- 来源全文通过独立浅灰区域体现附录层次，标题仍叫“来源全文”，不加“附录”二字；全文阅读字体、行距和内容保持。浅灰区域止于全文末尾，不包括来源说明或样稿对照说明。

## 样稿与实现边界
- 使用独立预览 Vault 对照原版内容与阅读样稿；具体真实笔记、Vault 配置和字体嵌入副本不纳入公开资料。
- 样式为可关闭的 CSS，关闭可恢复主题效果；正式交付的字体来源与许可需随实际资产保留。
- 为避免 Obsidian 虚拟化导致标题离屏后区域 CSS 失效，样稿全文用独立 HTML 容器，逐段文字已校验一致。这是样稿方案，不代表正式发布模板技术方案已定；推广至多格式来源需评估。
- 正式 SQLite 仅只读查询；未更改应用、正式发布模板、正式 Vault 笔记/外观配置，未迁移、删除媒体。首次预览建立后的保护文件哈希核对无差异。

## 验证与未决
- 在真实 Obsidian 阅读视图检查过白灰配色、字体、640px 样式、两列来源栏、折叠展开、紧凑证据和灰底区域。
- 观点/论证/证据与来源文字核对不变；来源时间来自正式材料 published_at。
- 页内入口已生成，自动点击曾被用户同步操作打断，完整定位回归未完成；最终显式全文容器改动后尚未做完整视觉/跳转复验。
- 仅单篇 X 文字样本；图文 OCR、多作者、长标题、缺失时间、多格式、窄窗口、导出、编辑视图等尚未验收。
- 整体主题目录/双链/跨篇组织尚未定；不发布 Insight 到 Obsidian 的当前边界未改变。与飞书需协调身份、来源时间、导航和未来新知发布范围。
- 旧产物 no-clobber 与用户批注保护、主题交付方式、区域 HTML 与 Markdown 可移植性、OCR 阅读稿与原始证据定位仍需工程方案。

## 媒体方向（来自主任务明确纠偏）
- 用户反对处理完成后长期保存过程视频/图片并嵌入 Obsidian；长期保留可读内容和来源链接。
- 必须一起处理展示和真实文件生命周期，不以隐藏嵌入代替清理；不扩展长期归档功能。
- 待明确处理中/待核对/失败重试的必要保留、完成后清理、数据库媒体/Vault附件/临时副本的实际范围和旧产物迁移。截图不能证明实际文件类型和体积。
- 删除后视听或图像再核查能力的取舍需明确；不擅自删除正式文件。

## 建议下一版范围及验收
- 优先实现既有成果的发布呈现与可关闭样式、来源元数据、证据完整展示、板块定位及全文区域边界。
- OCR 清理与媒体生命周期单独明确方案和验收，不与纯外观改动混为一谈。
- 验收：不增加来源观点语义、不丢证据/原文、不混用发表与蒸馏时间；同一内容可定位至对应栏目/依据；正文/依据/全文区分明确；来源说明在灰区外；中文窄窗口无溢出；旧文件批注不覆写；如执行媒体清理，失败恢复与真实副本占用也需验证。
