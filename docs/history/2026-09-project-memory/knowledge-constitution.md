# 知识库最小认知宪法

## 1. 正式定位

本宪法是：

> 知识派生边界及未来知识生长机制的上位认知约束。

它规定系统在记录、派生、判断、展示、修改和废止知识时，必须做到什么、不得做什么。

本宪法：

- 不依赖任何已有知识；
- 不依赖任何用户偏好；
- 不依赖任何模型；
- 约束系统，不约束用户；
- 不禁止系统形成判断，但禁止无归属、无依据、无谱系、不可修正的判断；
- 只规定权限与谱系，不规定永久对象类型、字段、状态机或存储方式；
- 不反向扩大当前最小 MVP。

它不是：

- 用户世界观或用户价值观；
- 用户内容偏好；
- 数据模型或 ontology；
- prompt 或 LLM 策略；
- 数据库设计；
- Obsidian 文件架构；
- 工程实现方案。

一句话定义：

> 知识库最小认知宪法是一组不依赖任何已有知识、用户偏好或模型的最小操作约束，规定系统在处理知识时永远不被允许的动作和永远必须做到的事。

宪法规定“系统能不能这样处理知识”，不规定“什么是真的、好的或重要的”。同一套约束必须能够原样用于任何领域：系统都必须忠实记录、保留可追溯依据，并不得因内容是否符合用户或系统偏好而偷偷修正。

内容可以从零开始，认知方法不能从零开始。知识库第一次处理素材时，就必须知道能否补写作者没有说完的话、如何处理无依据观点、是否保留冲突、能否把不确定表达升级为确定结论。这些底线不能成为某次 prompt 或某个模型默认倾向的副产物。

## 2. 最小认知宪法

### 原则一：归属与产生过程必须可追溯

任何正式知识表达都必须能够回答：

1. 这个知识主张归谁；
2. 这段表达由什么输入、经过什么过程形成。

系统必须区分：

- 来源作者在具体素材中的表达；
- 系统派生的判断；
- 用户自己的认知与评价。

不得存在无归属、无产生过程的正式知识。系统派生的新判断必须被明确识别为派生；用户表达必须被明确识别为用户认知。由 AI 组织生成的观点表述或完整论证，在表达上属于派生内容；凡被归属于作者的知识主张，必须确实由作者在对应素材中表达。

本原则只要求归属与过程可追溯，不规定永久的对象类型枚举。

正例：增生产生的新观点通过增生过程连接全部输入观点，并可继续穿透到各自证据。

反例：把系统归纳出的共同机制写成“作者认为”。

### 原则二：来源事实只读，下游不得回写上游

来源事实一旦按照来源事实契约成立，任何下游派生处理或用户行为都不得就地改写它。

发现来源事实可能有误时，只能：

- 请求来源恢复层重新核查；
- 或形成新的候选来源事实并重新验收。

系统不得为了让观点成立而修改来源，不得用外部常识替作者纠错，用户批注也不得改写来源。更好的识别能力重新处理历史素材时，必须先形成新的来源事实候选，不能自动覆盖已经接受的快照。

正例：知识蒸馏发现关键时间可疑，请求上游局部重听；上游重新通过验收后，再继续蒸馏。

反例：知识蒸馏层自行把听不清的数字改成更合理的值。

### 原则三：进入知识体系的任何主张都必须有可追溯依据或产生谱系

凡是要被用户看到、理解、判断或继续使用的知识主张，都必须能够说明其来历。

必须区分三种情况：

1. **正式结论**：必须达到对应的成立门槛，并具有完整、可追溯的依据链。
2. **候选观点／待验证假设**：可以尚未获得足以成为正式结论的证明，但必须具有明确的产生来源与推导依据，并显式标明候选或待验证状态。
3. **完全无依据的生成物**：不得成为正式知识，不得成为候选知识，也不得进入用户阅读层；必须直接丢弃。

典型依据链包括：

- 作者主张型观点 → 原文证据 → 内容快照 → 素材；
- 派生观点 → 产生过程 → 输入观点 → 各自依据；
- 观点关系或综合判断 → 形成该判断的依据与当前状态。

本宪法不规定依据必须永远是直接引用的原文片段。当前单素材 MVP 要求正式观点直接穿透来源证据，是其生产契约的当前落地形态。

正例：一条待验证假设明确说明由哪些观点与关系推导而来。

反例：模型顺手联想出一条新主张，说不清由什么知识触发，却仍进入候选列表。

### 原则四：不确定性必须显式，既不得升级，也不得用含糊掩盖

系统不得把不确定内容升级为确定内容，也不得用模糊措辞掩盖当前依据已经能够形成的真实判断。

系统必须：

- 给出当前依据能够支撑的明确表达；
- 标明其状态，例如当前判断、待验证假设或局部不确定；
- 保留形成判断的依据；
- 允许后续修正。

禁止的行为包括：

- 把“可能”改写成“表明”；
- 把个人经历或举例升级为普遍规律或因果论断；
- 把待验证假设写成正式结论；
- 依赖局部不确定内容生成比来源更强的主张；
- 用“存在联系”等含糊措辞代替当前可以形成的明确关系判断。

正例：无法确认的局部词句原位标明，不猜写、不删除，下游不依赖它形成更强观点。

反例：猜测一个听不清的数字并写入来源事实。

### 原则五：冲突信息必须保真——可以综合，不得静默消失

系统必须如实保留冲突信息。

系统可以：

- 分析冲突为什么产生；
- 识别条件、范围、定义或中介因素；
- 形成更精确的派生判断；
- 将当前最受支持的判断优先展示。

系统不得：

- 删除、覆盖或改写冲突各方；
- 把派生判断冒充成某一方的原意；
- 用折中措辞抹平原有冲突；
- 因为不符合用户倾向而丢弃一方；
- 切断用户下钻查看争议与依据的路径。

呈现浓缩不等于信息销毁。系统可以优先呈现综合判断，但原有冲突及其依据必须仍然存在并可追溯。

正例：保留 A 与 B 的相反主张，另行派生说明二者可能适用于不同条件的判断 C，并记录 C 的输入与依据。

反例：形成 C 后删除 A、B，或者把 A 改写成“作者其实是说要看条件”。

### 原则六：知识身份由核心主张决定

观点身份由其核心主张决定，不由文字外观或存储形式决定。

- 增加成立条件、收窄适用边界或提高表达精度，可以属于同一观点的演化；
- 核心主张被否定、反转或由另一主张替换时，产生新观点，并建立新观点对旧观点的修正／替代关系；
- 纯措辞润色不改变观点身份，也不形成观点历史。

观点身份不得由以下因素决定：

- 用户是否认同；
- 表达是否漂亮；
- 阅读排序；
- 使用的模型或 prompt；
- Markdown 文件、链接、引用编号或排版方式。

被替代的旧观点应保留其历史内容、当时依据和演化轨迹，但不再作为当前有效观点参与默认推理。

正例：新知识补充适用人群，使原观点边界收窄，属于同一观点的演化。

反例：更换模型后只有措辞不同，却被当成一个全新观点。

### 原则七：实质变化必须留痕，纯表达变化不留痕

知识语义发生实质变化时，必须能够回溯：

- 改变了什么；
- 为什么改变；
- 以前的判断及其依据；
- 当前什么判断有效。

必须留痕的变化包括核心主张、成立条件、适用边界、因果、关系含义和当前有效／历史状态的实质变化。历史内容不得删除，但不参与当前默认推理。

以下变化不要求形成历史：

- 纯文字润色；
- 不改变含义的改写；
- 纯阅读呈现变化；
- 不具有独立知识身份的轻量组织元素变化，例如排序、标题、阅读排版和标签标准化。

具有独立逻辑身份的组织索引对象，例如主题，在归并、拆分或重组时是否保存语义演化历史，由对应层未来自己的生产契约决定。本宪法既不提前豁免，也不提前强制。

正例：某观点关系由“因果”修正为“相关”，记录语义演化，并使旧关系退出当前推理。

反例：静默修改已入库观点的适用边界。

## 3. 仲裁总则

> **来源忠实与依据可核查，优先于流畅、浓缩与美观。**

蒸馏结果、标题、一句话总括、观点排序、核心／其他观点的阅读角色和完整论证，属于面向人的阅读组织层，可以重新生成。

阅读组织层的压缩、排序、重写和重新生成，不得改变：

- 归属；
- 依据；
- 来源事实；
- 条件；
- 因果；
- 强度；
- 结论。

阅读组织不得让系统派生主张看起来像作者说过的话，不得引入依据链不支持的知识，也不得切断读者回到依据的路径。

## 4. 三层权限结构

这里的三层是权限轴，与项目既有的“来源事实层／知识语义层／组织索引层”对象轴是两个不同坐标，不能相互覆盖或替代。

### 4.1 第一层：认知宪法

系统出生即存在，规定系统能不能以某种方式记录、派生、判断、展示、修改和废止知识。其余两层都不得违反本宪法。

### 4.2 第二层：用户认知底色

用户认知底色只能由长期真实使用中的高置信度主动反馈逐渐形成，例如用户主动投递、收录、遗弃或明确写下的批注。

它只有软影响权，可以渐进、局部、审慎、可批判地影响：

- 筛选；
- 内容处理；
- 组织；
- 关联判断；
- 候选生成；
- 呈现。

它没有改写权，不得直接改写来源事实、正式观点或正式关系，不得因用户不认同而删除、压缩或曲解外部知识，也不得把用户偏好冒充成外部事实。

用户认知与外部来源冲突时，两者分别成立、互不覆盖。用户批注记录用户如何回应，来源与观点记录外部实际表达了什么。相互冲突的新旧用户批注全部保留；推断当前倾向时可以提高较新批注的权重，但不能抹去历史。

### 4.3 第三层：具体知识

具体知识保存外部来源实际表达、证据、观点、关系、派生结果、用户认知以及对应谱系。

其中：

- 来源事实保持只读；
- 派生知识必须具有依据和谱系；
- 用户认知只代表用户；
- 任何一类内容都不得冒充另一类内容。

一句话概括：

> 宪法管“能不能这么做”；用户认知底色拥有软影响权而不是改写权；具体知识管“知识库里到底有什么”。

## 5. 明确不属于认知宪法的内容

以下内容不得进入认知宪法：

- 用户偏好的领域、作者或分析角度；
- 用户世界观与价值判断；
- 具体领域立场；
- 预设的来源权威等级，例如仅凭“官方／自媒体”“专家／个人经验”或“新／旧”自动裁决知识；
- 除“是否有可追溯依据”等过程约束外，对什么主题重要、什么观点值得保留的内容标准；
- 只能由长期真实使用逐渐形成的个性化倾向；
- 标题长度、观点数量、行文口吻、文件结构等呈现参数。

判断一条规则是否越权的方法是：把它应用到一份用户完全不认同的素材上。如果它会让系统删除、曲解或压缩来源实际表达的知识，或者把用户偏好写成外部事实，它就不属于认知宪法。

## 6. 当前最小 MVP 的继承边界

当前最小 MVP 仍然只处理：

> 单条抖音口播可信内容快照 → 单素材可核查知识结果。

本宪法在当前 MVP 中落实为：

- 来源事实与 AI 派生知识必须分离；
- 已接受的内容快照对下游只读；
- 每个正式观点只能来自作者在当前素材中实际表达的知识主张；
- 每个正式观点必须显式关联一个或多个真正支持它的来源证据；
- 证据必须稳定定位回可信内容快照；
- 局部不确定内容不得被当作确定事实，也不得被用于形成更强知识主张；
- 无法可靠恢复原意时必须失败，不得入库；
- 单素材内部矛盾、自我修正、条件不一致或作者自身事实错误不得被系统偷偷抹平或代为纠正；
- 观点身份不由模型、prompt、排序、Markdown、链接或引用编号决定；
- 标题、总括、观点排序、核心／其他观点角色和完整论证可以重新生成，但不得改变知识语义与依据；
- 来源忠实与依据可核查高于文案流畅、浓缩和美观。

当前 MVP 不因此新增：

- 知识结果版本系统；
- 自动 diff；
- 观点演化管理；
- 用户认知学习；
- 多来源冲突综合；
- 手动增生；
- 主题版本治理；
- 数据模型、schema、ID 或数据库；
- prompt、模型或调用策略；
- Obsidian 文件架构。

以上长期条款在后续阶段的具体落地形式，必须由对应边界的生产契约另行确定。本宪法既不提前实现这些能力，也不得被用来阻碍未来在相同认知边界内扩展。

## 7. 未来阶段的适用边界

以下内容只确认未来阶段必须继续遵守的认知边界，不代表当前开始设计或实现对应能力：

- 手动增生启用后，候选观点与待验证假设必须保留产生过程、输入观点和推导依据；完全无依据的生成物直接丢弃，不进入候选列表。
- 多来源综合启用后，可以解释冲突并形成更精确的派生判断，但冲突各方、证据和来源路径必须全部保留并可下钻。
- 用户反馈学习启用后，用户认知底色只能作为渐进、局部、审慎、可批判的软信号，影响筛选、处理、组织、关联、候选生成和呈现，不能直接改写来源事实或正式知识语义。
- 观点与关系演化启用后，核心主张、关系含义和适用边界的实质变化必须保留修正／替代谱系；纯措辞变化不形成历史。
- 主题索引启用后，可以提供高度浓缩的当前判断，但争议与依据必须仍可下钻；主题作为独立组织索引对象是否保存归并、拆分和重组历史，由主题层自己的生产契约决定。
- 蒸馏方法可以持续升级，但方法版本演化与具体历史知识是否重新处理必须分开治理，不能因方法升级而无条件重处理历史知识。
