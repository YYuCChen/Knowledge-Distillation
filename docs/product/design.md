# 设计维护原则

修复附近缺陷时保持已认可控件的职责、视觉等级和交互。共用CSS变动需要检查其他被命中的控件；把所有按钮改成同一强调程度，即使页面能显示，也可能破坏用户流程。

投递、待核对、失败和正式知识应有清晰含义，不把内部队列和存储机制无必要地暴露给用户。不显示虚构进度、预计时间或没有真实记录支撑的完成状态。

标题、摘要、观点、论证、证据承担不同阅读角色。观点应有必要上下文并能回到依据，保留来源归属，同时避免每句都成为重复的旁观者报告。

使用真实长内容、窄窗和失败/核对状态检查布局。一张好看的样稿或模板字符串断言不能证明视觉忠实度。除非任务明确改版，保留用户认可的字体、留白和动作等级。

设计资产、未来探索与已发布能力分开。样稿和私人Vault示例不建立产品已上线事实。公开示例必须使用合成或已获准内容，不公开私人笔记与真实用户截图。
