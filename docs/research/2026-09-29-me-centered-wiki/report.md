# 以"我"为中心的个人知识库：Wiki 结构调研与方案

调研日期：2026-09-29。方法：三路低成本模型并行检索（结果见同目录 A/B/C 三个文件，均附来源链接，未能核实的内容已注明），由 Agent 综合。本文为方案草案，需用户确认后才写入决策记录。

## 一、调研得出的共识

1. **三层分离**（Karpathy LLM Wiki 及其 v2/v3 扩展）：不可变的原始证据 → LLM 维护的 wiki 页面 → 人写的规则（schema）。另配只追加的 `log` 和作为目录的 `index`。v3 的批评指出：wiki 不能成为唯一的真相来源，每个说法都必须链接回原始证据。
2. **常驻小核心 + 按需主题页 + 只追加日志**（Letta 的 core memory、Claude Code 的 MEMORY.md、LangMem、ChatGPT memory）：关于用户的核心信息压缩成一份短文档（约 200 行以内），每次都读；细节放在主题页里按需读取；事件按时间只追加。
3. **时间：双时态、只增不改**（Zep/Graphiti、Mem0、双时态数据）：区分"事实在现实中成立的时间"和"系统记录的时间"。更正时关闭旧记录、新增新记录，不覆盖。"当前状态"放在可以覆盖的档案页里，历史放在带日期的条目里。
4. **人写与 AI 写分开，AI 写入要过闸门**（Claude Code 的 CLAUDE.md 与 auto memory 分工、MyContext 的审核后入库）。反面教训：Mem0 的一次生产审计中，10,134 条自动抽取的记忆有 97.8% 是垃圾，包括编造的用户画像，以及召回内容被当成新事实再次抽取。
5. **结构要靠挣得**（Nick Milo 的 ACE 框架）：顶层很少（ACE 只有 知识 / 时间 / 行动 三个空间）；一个主题积累到大约 5 条笔记以上，才为它建 MOC 索引。耐用的是追加式的日期笔记、少量顶层目录，以及从记录中推导出来的信息；容易腐烂的是按状态搬家的文件夹、需要手填维护的字段、过深的层级。
6. **以"我"为圆心的蜘蛛网**（个人知识图谱研究，Balog & Kenter 2019）：每个实体都直接或间接连回"我"。语句要区分客观事实、个人事件、我的看法、他人的观点，并各自带上出处、时间和置信度。
7. **"我"的三层**（McAdams 的人格三层）：稳定倾向（很少变化）→ 目标、关切与现状（中频变化，有有效期）→ 人生叙事（只能来自本人的讲述）。三层的更新频率和证据标准都不同。
8. **不做全量记录**（MyLifeBits 的教训；Memex 的"路径"思想）：瓶颈在于找回和组织，而不在于存储。应当精选、链接、注释，用个人路径把内容串起来，而不是堆积原始记录。

## 二、方案草案

### 顶层结构（Obsidian vault）

```
vault/
  _规则.md            人写：这个库的约定（相当于 schema），AI 必须遵守
  我.md               核心档案：常驻、简短，AI 每次必读
  时间线/2026/09/2026-09-29.md
                      只追加：想法、事件、决定、反思，逐条带编号和类型
  在做/               努力（项目、长期事务），状态是字段而不是文件夹
  关切/               我反复回到的问题；靠积累"挣得"，经我确认后建立
  人/                 人物页；往来历史从时间线中推导
  来源/               所见：外部材料（一期的来源笔记），原样保存
  .kd/                机器层：锚点、关系、双时态事实库、log、index
```

### 页面类型（封闭的一小组，schema 强制）

| 类型 | 对应的"我"的面向 | 谁写 | 可变性 |
|---|---|---|---|
| `我`（单页） | 所处、所好、关切概览 | AI 起草，**我审核** | 可覆盖，每次改动留日志 |
| 时间线条目 | 所思、所历、所为 | 我（原话），或由捕捉通道写入 | 只追加 |
| 努力 | 所处、所为 | AI 维护，我确认创建 | 正文可重写，状态有历史 |
| 关切 | 所思的长期重心 | AI 维护，我确认创建 | 正文可重写 |
| 人 | 所历 | AI 维护 | 正文可重写 |
| 来源 | 所见 | 采集链路 | 不可变 |

`我.md` 的分区对应 McAdams 三层：稳定倾向与原则 / 当前关切、目标与现状（带有效期）/ 我的叙事（只收录本人原话）。每一行都链接到支撑它的详情页或时间线条目。

### 语句与元数据

每条结构化语句都标注：类型（事实 / 事件 / 我的看法 / 他人观点 / AI 推断）、出处（链接到时间线条目或来源）、`recorded_at`；状态类事实另加 `valid_from` / `valid_to`；AI 推断还要标注置信度。更正时关闭旧记录，不覆盖。

### 维护操作（沿用 LLM Wiki）

- **收录（ingest）**：每条输入流一个适配器，包括所见（一期链路）、所思（飞书随手记）、所为（与 AI 的对话、项目文档等），统一写入时间线或来源，再更新相关页面。
- **问答（query）**：回答时读取 `我.md` 和相关页面；值得保留的回答以"AI 推断"的身份回写，并且要过闸门。
- **体检（lint）**：检查矛盾、过期（超过有效期或长期没有被提及）、孤立页面、重复抽取。

### 闸门（防止 Mem0 式的污染）

- 对 `我.md` 的改动，以及新建"关切"和"努力"页，一律作为提议（铅笔线），经我确认后才生效。
- 从召回内容里抽取出来的东西不得作为新事实；AI 推断不能成为另一条 AI 推断的依据（与决策 0002 的铅笔线、墨水线规则一致）。
- 宁可少写：只有达到阈值（例如同一关切积累 5 条以上条目、同一个人出现 3 次以上）才建立结构。

## 三、与此前讨论的衔接

- 结构不从材料里推算，也不借用世界目录。它锚定在"我"生活中天然稳定的实体上：我、时间、我在做的事、我的关切、我身边的人。公共知识的结构交给 AI 自身。
- 一期的主题页由"关切"页取代；来源笔记整体归入 `来源/`；锚点和关系作为 `.kd/` 中的机器层，继续服务于"所见"材料之间的连接。
- 决策 0002 中关于"不可再生 / 可再生"、身份边界、铅笔线的原则全部沿用。
