## 背景

一期完成了从采集到收录的来源事实层和较薄的观点层。二期的远期目标，是把它发展成一个可成长、能自我维护的个人知识库。讨论中参考了 LLM Wiki 模式（Karpathy：原始资料 / LLM 维护的 wiki / schema，以及 ingest / query / lint 三种操作）和 TypeSafe 的 Jev（封闭选项、带校准概率的快速判断模型）。

## 决定

### 1. 二期定位：先落档，不以问题驱动

模型能力仍在快速进步，当前材料量也不足，现在就以具体问题驱动知识库容易落空。二期的首要目标，是把日常看到、想到的各类材料整齐归档，在保证综合保真度的前提下尽量降低熵，为将来更强的模型调用和知识库的自我成长做准备。

### 2. 资产分为不可再生和可再生两类

- **不可再生，只增不改，严格保真**：来源材料与来源事实，用户的原话、判断、反应和表态，以及它们发生的时间和上下文。
- **可再生缓存**：AI 推出的观点、关系、锚点、新知、回应、taste 描述等。它们必须锚定在不可再生层上，可以被更强的模型整体重算。
- 这样可以防止"在错误的推断上继续叠加错误"：AI 层的错误不会变成永久的地基。

### 3. 知识库以机器为主要读者，人读投影

正式形态是结构化数据，主要供 AI 取用。人读的是按需生成的投影，例如回顾、回应、问答结果。人读的价值偏认知和思考，机器读的价值偏实用和功能。

### 4. 关系层先做概念/实体锚点

- 锚点只负责"同一性"：把不同材料里谈论的同一个东西归到一处。锚点只做链接，从不合并或改写原文。
- 锚点记录包含：稳定编号、类型（概念/实体，边界可以宽松）、首选名、别名、判别说明（指什么、不指什么）、挂靠的观点（核心或顺带）、上位/相关关系。设计参照 SKOS 叙词表，不做重型本体。
- **身份靠编号，不靠名字。** 同一个词在不同领域可能含义完全不同（样本中"压缩"就有四种含义），因此不能按名字建立链接。
- 锚点不做给人读的页面。vault 里保留一份机器可读的备份，保证数据可以脱离应用存在。人需要看时再按需生成。
- 跨领域的类比和结构相似（例如"幻觉回写"与"五行闭环"）不合并成锚点，交给派生/新知层处理。
- 观点之间的关系，例如"对策应对现象"，属于观点关系层，不放进锚点层。
- 识别分两步：发现新概念由大模型完成，低频；把观点挂靠到已有锚点是封闭判断，高频且便宜，适合 Jev 或小模型。
- 2026-09-28 用 9 篇真实笔记做了验证：锚点取材的准确度明显优于字面搜索，而且能完成跨领域连接。验证判定方向成立，细节留待使用中迭代。

### 5. 个人表达采用折中方案

- 原话原样保存，不拆成主张，也不生成"整理稿"。原话里的语气和转折本身就是有价值的信号。
- 个人表达和外部材料共用同一套概念锚点。外部材料可以"回应"个人表达，用对话式的类型：呼应、挑战、补充视角，而不是支持/反驳这类判定。回应只能引用库里已有的观点和证据。刻意保留"挑战"，避免回音室。
- 默认不能被 AI 当作推理前提。用户可以主动把一段表达"升格"为自己的主张。
- 个人层有四种关系：触发（什么引发了这段表达）、回应、用户反应、演变（延续或转变只能由用户确认）。
- taste 只保存原始信号事件；由此归纳的描述属于可再生派生物，只有软影响力，不能替用户过滤外部知识。

### 6. 捕捉与回应的节奏

- 入口是飞书单窗口：材料和想法发在同一个对话里，因为两者之间可能本来就有思考关系。捕捉时只回"已记录"，不追问，不做分析。
- 回应默认沉淀：定期回顾（被动），并把时间差和发酵过程一起纳入。深挖在用户回到桌前时发生（主动）。
- 语音只保留高还原度的转写原文，识别疑点走现有的待办订正路径。
- 三个判断按风险分级处理：身份（我 / 第三方 / 附言）拿不准时进待办；触发关系始终只作提议；碎片聚合可以自动执行，且可拆开。
- 飞书端由 Claude（在 Code 模式中）实现，需求见[飞书随手记需求说明](../roadmap/handoff-feishu-capture.md)。

### 7. 工作面：读在 Obsidian，做在 Local Web，随手记在飞书（2026-09-28 修订）

- **Obsidian 是图书馆**，分为两类区域：
  - **馆藏**：来源笔记（保持现状，不附加关联信息）和 `我/随手记/`（用户原话，按天只追加），原样保存，永不修改。
  - **导览**：`导览/` 由应用维护，可以随时重写，每页开头注明"本页由 AI 维护"。
  - 另有隐藏目录 `.kd/` 存放机器数据：锚点、关系，以及用户判断和反应信号的备份。它随 vault 一起保存，但不打扰阅读。
- **Local Web 是工作台**：投递、处理队列、核对疑点、对新知和 AI 提议做出反应。新知页扩展为"研讨室"，承接 AI 的提议和回顾中需要操作的部分。扩展必须基于设计母版，先出设计稿并经用户确认。
- **飞书是随身入口**：随手记、投递材料、少量轻操作。
- 每个区域只有一个写入者，从而避免双向同步。不可再生的内容必须在文件里有一份；SQLite 负责结构层和索引。远期可以提供面向 AI 的查询接口（例如 MCP）。
- 用户目前主要在电脑上使用 Obsidian，手机端暂不考虑。

### 8. 关系层：只在锚点内比较，多维记录，铅笔线与墨水线

- **只在锚点内比较**：新观点入库时，只与挂在同一锚点上的观点比较，不做全库两两比较。计算量取决于锚点的规模，不会随全库增长而爆炸。
- **大部分关系属于可再生缓存**，将来的模型可以现场重算。必须保存的只有：用户确认或驳回过的关系，以及冲突（认知宪法要求冲突保真）。
- **关系是一条多维记录，不是单一标签**。每个维度都是封闭选择，适合 Jev 或小模型判断：
  - 立场：同向 / 相反 / 无关立场
  - 逻辑作用：证据、前提、推论、条件与边界、对策、实例、机制解释
  - 层次：事实层 / 判断层 / 方法层 / 价值层
  - 适用条件：一句简短说明，可以留空
  - 依据：两端各自的原文证据
  以后可以增加维度（例如时效），不会破坏已有数据。
- **状态：铅笔线与墨水线**。
  - AI 的提议是铅笔线，可以用于检索和组织回应，但**不能作为继续推理的前提**。
  - 用户确认过的，或高置信并且两端都有原文证据的，是墨水线。
  - 被驳回的关系保留记录，不删除。
  只有当某条铅笔线要被用作推理前提，或者它是一个冲突时，才请用户确认。
- 跨领域的类比不在关系层处理，交给新知层。一期为新知服务的自由文本关系保持不变，与新的关系层并存。

### 9. 新知的定位

新知不上架 Obsidian，定位为"廉价的思绪启迪器"：用来引发思考，同时让系统观察到一部分用户偏好。用户对新知的反应（有点意思、再想想、批注、追加的想法）是不可再生的偏好信号，必须保存，并备份到 `.kd/`。

## 按可逆性分类

**可逆，放手迭代**：锚点粒度与升格门槛（当前倾向：出现在第二份材料时自动升格）、关系维度与选项、导览的形式与语气（定为克制、平实、直接给判断）、判断模型选型（规则 / Jev / 大模型）与阈值、回顾的形式与频率、所有界面呈现。

**不可逆，必须论证**：

| 项目 | 状态 |
|---|---|
| 不可再生数据完整留存（原话、时间、上下文邻接、用户判断事件） | 方向已定；捕捉端细节见飞书需求说明 |
| 观点身份稳定 | 底线已由现有设计保证：观点身份为 `(knowledge_result_id, point_id)`，`knowledge_results` 由触发器保证不可修改、不可删除；用户判断挂在当时看到的具体版本上。重新蒸馏目前不是既定场景（可能来自来源订正、方法升级或模型升级）。真正需要时，按以下方式处理：旧版本退役不覆盖，新旧观点用可再生的对应表连接（可借助引用原文位置是否重叠），用户判断不自动迁移。这部分属于可逆设计，届时再定。 |
| 身份靠编号不靠名字 | 已定 |
| 用户对关系的确认和驳回，作为事件保存并挂在具体的观点版本上 | 已定 |
| 铅笔线（提议）不得作为推理前提 | 已定 |
| 用户的策展动作（给导览区块改名、固定、合并）和对新知的反应，作为事件保存 | 已定 |
| "我"与第三方的身份边界 | 已定：拿不准时进待办，不自动入库 |
| vault 文件格式与所有权划分 | 方向已定：按区域单写入者，具体目录结构待落地时定 |

## 与既有约束的关系

认知宪法（归属、来源只读、依据可追溯、不确定性显式、冲突保真、身份由核心主张决定、实质变化留痕）继续有效。本决策是在它之上的二期落地方向。已定稿的 UI 仍须经用户同意才能修改。
