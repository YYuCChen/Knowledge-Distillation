# 决策0001：实现、意图与存储分开治理

## 背景

源码公开可能没有包含私人或未跟踪的产品文档。如果认为一切有用内容都已在Git，就可能在退役旧工程时丢失未来构想和用户裁决。反过来，永久保留所有模型与测试数据库也不能改善项目记忆。

## 决定

公开仓库作为代码开发基线；用实际源码/发布证据描述已实现能力；有效产品裁决与未来探索分别维护，标明状态。私人原件在公开树之外保全，只有审阅过的工程/产品内容公开。

未来构想即使未排期、未实现也受保护。讨论建议不能升级为用户承诺。退出旧文档的默认权威不等于可以删除其独有内容。

## 结果

新任务从短文档入口读取相关规范；行为变更更新所属正文。私人对话和混合旧历史不整体上传。清理是在保全结果并确认归属后移除可重建产物，不把旧版本等同于垃圾。

公开文档发布后，仓库维护的版本成为公开正文；本地审阅副本转为交付记录，不形成第二套日常编辑来源。
