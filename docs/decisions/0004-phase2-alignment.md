# 决策0004：二期三方对齐——应用供料，Agent 维护 wiki

状态：已定（2026-09-29 用户逐项确认）。执行时遵守 [AGENTS.md 最高工作原则](../../AGENTS.md)。本决策是二期开发的现行依据，与 [决策0002](0002-phase2-knowledge-backbone.md)、[决策0003](0003-material-foundation.md) 冲突时以本决策为准。

## 背景

二期方案来自三方材料，彼此没有对齐过：

1. **现有产品**：公开 main = V1.3（构建 2026.09.15.6）。SQLite 是正式记录，Obsidian 只接收来源型笔记。
2. **第一次讨论**（2026-09-28～29）：经历锚点、关系、导览、"关于我"等多轮试错，最终收敛到决策0003"素材基座：只洗净、切配，不调味"。过程中留下了若干与路线无关的硬要求。原始记录见 [二期讨论进展](../roadmap/phase2-discussion.md)。
3. **第二次讨论**（2026-09-29，脱离旧上下文重新设计）：形成定版方案，即 [个人知识系统方案](../product/phase2-knowledge-system.md)，以及随附的 vault 维护守则和检查脚本（见 [`vault-kit/`](../../vault-kit/)）。

本决策把三者粘合为一套可开发的依据。

## 决定

### 1. 二期形态：两件事，一个接口

- **应用**（本仓库现有代码）继续负责：采集、洗净、切配、飞书随手记、识别疑点核对。它把素材稳定地写入 vault 的 `raw/`。
- **wiki 的维护**交给外部 Agent（Codex、Claude Code、DeepSeek 等，可在 Obsidian 的 Claudian 插件里使用）。Agent 读 vault 根目录的 AGENTS.md，运行 `tools/kb.py`。
- **两边唯一的接口是 `raw/` 的目录与文件格式**，规格见 [raw 接口规格](../engineering/raw-interface.md)。
- 维护由用户主动发起（如"处理新素材""做一次体检"）。二期不做定时任务；以后可以在所用 Agent 工具里另加。
- 二期只做 macOS，Windows 冻结不维护（2026-09-28 用户裁决）。

### 2. 逐项裁决

标 ★ 的是不可逆或迁移成本高的项。

| # | 事项 | 裁决 |
|---|---|---|
| D1 ★ | 正本边界 | 应用的 SQLite 管"加工过程"（任务、疑点、订正事件、飞书收据）。vault 的 `raw/` 是知识库正本，`wiki/` 由 raw 派生。0003 中"仅凭 vault 可重建数据库"收窄为"仅凭 vault 可重建知识库"。 |
| D2 ★ | raw 目录 | `raw/外部/YYYY/MM/`、`raw/自述/YYYY/MM/`、`raw/数据/`。文件名为素材编号，不含空格。0003 的 `素材/YYYY/MM/` 作废。 |

| D4 ★ | 身份：编号还是名字 | 分层：**raw 靠编号**（不可逆，永不改变）；**wiki 靠标题**（可从 raw 重建）。同名异义用括注区分，如 `压缩（信息论）`，写入 vault 守则。 |
| D5 | V1 蒸馏笔记 | 继续生成到 `知识蒸馏器/`，作为用户在 Obsidian 的阅读版。它不进入 raw，也不作为 wiki 依据；wiki 来源页一律从 raw 生成。 |

| D7 | 确认在哪里做 | wiki 候选（认知、方法、实践、技能、触发关联、反例）在用户与维护 Agent 的对话中确认，依据 `wiki/待确认.md`。应用侧只处理素材层待办：识别疑点、随手记身份待定，沿用现有疑点卡与待办样式。 |

| D9 | AI 对话中本人发言 | 由维护 Agent 存入 `raw/自述/`，只新建文件，不改已有文件。vault 守则的"raw 只读"铁律相应补充这一例外。 |
| D10 | 两份 AGENTS.md | 仓库根目录的 AGENTS.md 是**开发规则**，vault 根目录的 AGENTS.md 是**知识维护守则**，两者严格分开。vault 守则、`kb.py` 以及快捷命令的正本放在本仓库 `vault-kit/`，有版本记录；首次手动安装到 vault，以后随版本升级。vault 另放一份 CLAUDE.md 指向 AGENTS.md，使 Claude Code 与 Codex 读到同一份守则。 |
| D11 | 开发基线 | 从 main 新建分支 `phase2/foundation`。第一次讨论的 0002、0003、讨论记录、飞书需求、调研一并带入，被取代的部分加注，不删除。 |
| D12 | 存量素材 | 一次性从 V1 数据库的来源原文（`source_facts`）导出到 `raw/外部/`，不从笔记反推。原笔记不动。 |
| D13 | kb.py 适配 | 支持 `raw/…/编号.md#^source-N` 形式的段落引用；其余适配见 raw 接口规格第 8 节。 |

### 3. 从第一次讨论保留的要求

- **最高工作原则**：已写入仓库 [AGENTS.md](../../AGENTS.md)。
- **协作方式**：在 Chat 里谈需求，在 Claude Code 里落地；二期由 Claude 开发。
- **分工**：读在 Obsidian，做在 Local Web，随手记在飞书。
- **随手记**：
  - 同一个窗口收发；捕捉时零摩擦，只回"已记录"。
  - 原话不做整理稿。
  - 录音在疑点处理完后释放。
  - 订正保留 ASR 原稿。
  - 身份拿不准时进待办，不自动归为本人。
  - 邻接上下文在捕捉时记录。
  - 提供云端判断开关。
- **新知**：不上架。用户对新知的反应是偏好信号，V1 数据库已保存；是否导出到 raw 见第 5 节。
- **UI**：一切界面工作都基于设计母版。已定稿的 UI，改动前须经用户同意。新增待办沿用疑点卡样式。

## 可逆性

- **不可逆，已论证**：
  - raw 是知识库正本，且只进不改；
  - raw 编号与内容无关，永不改变；
  - 段落片段一经写入不再改动；
  - 本人与第三方的身份边界，拿不准时进待办；
  - 捕捉时记录邻接事实；
  - ASR 原稿随订正一并保留；
  - 媒体删除必须由用户按类别裁决（随手记录音已裁决为疑点处理后释放）。
- **可逆，放手迭代**：
  - wiki 的页面类型与模板、主题列表、快捷命令；
  - kb.py 的实现细节；
  - V1 主题页、新知页的去留；
  - 是否加定时维护；
  - raw 信封中非必填字段的增减（须向后兼容）。
