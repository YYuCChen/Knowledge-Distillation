## BUG-20260912-01：来源整理局部纠错失败的留证、恢复与提示

状态：已在 V1.2（构建 2026.09.13.3）实现并发布；下列原始验收要求保留用于追溯。原始运行记录包含真实知识数据，保留本地；这里只记录通用问题与验收要求。

问题：局部纠错候选因引用、定位或结构不合法而被拒绝时，当前失败提示不足以帮助判断原因，也不能用放松事实校验的方式解决。

目标行为：

1. 保留必要的原转写、模型响应及具体失败索引/字段，便于定位。诊断数据留本地，按问题处理与保留期限管理，不能上传真实内容作为公开夹具。
2. 证据引用必须与来源中的连续原文匹配；需要多段证据时分别保存位置与验证，不把拼接片段伪装成一段原文。
3. 针对明确失败原因进行一次有界修复重试。仍不合法时，保留对应原文并标明未解决；定位不可靠则保留完整原段，不能猜改或丢失来源。
4. 用户提示准确说明原文已保留、还有哪些必要核对，不以笼统失败覆盖实际结果。
5. 未经验证的修复不成为正式事实；不能无限重试，也不能因局部失败阻止其他可安全继续的部分。

验收用合成样本覆盖：拼接引用、字面不匹配、区间重叠、定位失败、重试仍失败。确认原文保留、无非法事实入库、诊断可定位、重试有上限、其他安全分支不受阻，并运行相关回归。

该待办不授权重新处理任何真实用户任务，也不把某次人工放行推广成自动通过规则。

## F-11：统一 Local Web“开始整理”与 Vault wiki 整理入口

状态：用户于 2026-09-30 提出合并方向，已纳入 [V3.0 施工包](v3-plan.md)；开工前决定和设计样稿仍待确认，尚未授权业务代码或正式 Vault 改动。

当前两个动作在用户目标上都是“把新积累联系起来”，但实现并不相同：Local Web 从 SQLite 的来源知识生成 Topic、关系和新知，Claudian 从 Vault `raw/` 生成来源页、概念页、个人认知候选和关系图。把两套现有流程简单绑在同一按钮上会重复消耗模型额度，并产生两套可能不一致的知识结果，因此不采用表面双跑。

推荐在下一大版本做真正统一：以 `raw/` 为唯一整理输入、Vault wiki 为新的派生知识权威；Local Web 的“开始整理”成为统一入口和状态面板，后台调用独立的 wiki 维护 runner，完成后引导查看待确认。现有 SQLite Topic、新知和用户判断先只读保留，逐项设计可验证迁移，不能静默删除或把 AI 新知冒充用户认知。该方向涉及定稿 UI、后台任务生命周期、Agent 账号/失败恢复以及既有不可再生判断的迁移，须按大版本完成设计与验收。

## F-12：统一 Obsidian wiki 与既有阅读版的排版和视觉语言

状态：用户于 2026-10-01 明确列入下一版本，已纳入 [V3.0 施工包](v3-plan.md)；本轮只完成准备，尚未设计或修改正式 Vault。

问题：V2.0 新增的 `wiki/` 页面沿用通用 Markdown 与属性面板，和原有 `知识蒸馏器/` 阅读版的排版、颜色、内容层级及阅读感受不一致。文件侧栏里的 `raw/`、`skills/`、`tools/`、`AGENTS`、`CLAUDE` 等维护入口也与日常阅读入口混在一起，技术结构过于显眼。现有阅读版以 [Obsidian 阅读阶段结论](../history/2026-09-project-memory/obsidian-reading.md)及正式 Vault 的可关闭 `kd-reading.css` 为已认可基线；下一版不能凭工程便利另造一套风格。

目标范围：

1. 先核对正式 Vault 当时实际使用的主题、CSS snippet、字体、阅读视图、编辑视图和侧栏结构，再从既有阅读版提炼统一规则；旧记录或截图不能代替真实基线。
2. 为来源、概念、认知、方法、技能、实践、综合、主题，以及 `index`、待确认、体检报告、log 等系统页设计一致的标题、正文、属性、引用、链接、自动区块和状态层级；不同页面仍须保留清晰身份，不能只把所有页面套成同一模板。
3. 同时优化日常导航与维护结构的呈现。`raw/`、技能、工具和 Agent 规则仍是系统运行接口，不得为了侧栏好看而擅自移动、改名或隐藏到 Agent 无法发现；如需弱化其可见性，应优先使用可逆的呈现层方案，并保留明确的知识入口。
4. 排版改动与知识语义解耦：不改 `raw/` 正本，不改稳定编号、链接、证据、确认状态和自动生成边界，不用批量重写内容来制造视觉一致。
5. 先制作覆盖主要页面类型的代表性样稿，在真实 Obsidian 中与既有阅读版并排检查，经用户确认后再批量应用。样式应可关闭、可回退，不锁死于单个 Agent 或私有插件。

验收至少覆盖：既有阅读页与新 wiki 页并存；长标题、长属性、多段正文、引用、双链和自动区块；正常宽度与窄窗口；阅读视图与编辑视图；侧栏的日常入口和技术入口可辨。验证内容、证据和链接在样式启用前后完全不变，并记录所依赖的主题、snippet、插件与回退方式。
