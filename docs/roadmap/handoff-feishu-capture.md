# 需求说明：飞书随手记

> 2026-09-29 更新：按[决策0004](../decisions/0004-phase2-alignment.md) D8，4.4 节的碎片聚合与触发提议移出应用、交给 wiki 层；落档格式以 [raw 接口规格](../engineering/raw-interface.md)为准。其余要求，尤其是【不可逆】条款，继续有效。


状态：待实现，由 Claude 在 Code 模式中开发。依据：[决策0002](../decisions/0002-phase2-knowledge-backbone.md)。执行时遵守 [AGENTS.md 最高工作原则](../../AGENTS.md)：本说明中标为 **【不可逆】** 的要求必须严格做到；其余属于可逆细节，可以按工程上最顺手的方式实现，交付时说明所做的取舍。

## 1. 要解决什么

用户的灵感常出现在开车、骑车、散步等不便写字的时刻，转瞬即逝。飞书是现有的投递入口。目标是让用户在**同一个已绑定的私聊窗口**里，用语音或文字随手留下想法的片段，由系统可靠地落档。这些记录是二期个人知识层最基础、不可再生的原料。

材料投递和想法记录共用一个窗口，因为两者之间常有思考上的关联。现有的材料投递行为保持不变。

## 2. 用户体验要求

- 捕捉时零摩擦：收到后只回一句确认（例如"已记录"），**不追问、不做分析、不要求分类或核对**。
- 深挖不在捕捉时发生。本需求不包含任何即时回应或对话式分析。
- 支持文字和语音。语音消息需要接入音频附件（README 目前写的是"不支持音频附件"），复用现有的 ASR 能力（Qwen / 豆包）转写。

## 3. 消息身份判断

每条非链接消息需要判断身份：`my_thought`（我的想法）、`third_party`（转发或粘贴的第三方内容）、`annotation`（对刚投递材料的附言，例如"这篇重点看后半段"）。

- 先用规则判断：含链接的按现有材料投递处理；语音默认为 `my_thought`；大段、带格式、明显是转载的文本倾向 `third_party`。规则判不了的，再交给可替换的判断接口（先用现有 LLM 连接实现；接口保持抽象，以后可以换成 Jev 或本地模型）。
- **【不可逆】身份拿不准时不得自动归入 `my_thought`。** 这类消息标记为"身份待定"，进入现有的待办 / 待你操作路径，由用户在桌前判断。第三方内容误入个人层属于污染，难以清理。
- 记录每次判断的来源（规则 / 哪个模型）、结果和置信度；用户的改判作为事件记录，不覆盖原判断。
- 发送给云端模型的是用户最私密的内容。需要在设置中提供开关：关闭时只用规则，判不了的一律进待办。

## 4. 落档：数据要求

### 4.1 原始记录【不可逆】

每条消息都存为一条**不可修改**的捕捉记录，至少包括：

- 稳定的捕捉编号（与文本内容无关，永不改变）；
- 飞书 message_id、接收时间（毫秒）、消息类型（文字 / 语音）；
- 文字消息的原文；语音消息的 ASR 转写原文，以及所用 ASR 引擎、模型和版本；
- **不做润色，不生成"整理稿"**。原话中的语气词、停顿和改口（"不对，应该说……"）必须原样保留。

实现上优先复用 `feishu_receipts`，可新建关联表，但原始记录需要有数据库层面的不可修改保护（参照 `knowledge_results` 的触发器做法）。

### 4.2 转写订正【不可逆】

- 语音转写中影响理解的识别疑点，走现有的疑点 / 待办订正路径。
- 订正以**新版本或订正事件**的形式保存，**必须保留 ASR 原始转写**，不能就地覆盖。
- 音频只需保留到该条记录的疑点处理完毕（需要回听），之后按现有 `media_lifecycle` 释放字节，但保留"曾有音频、已释放"的记录。用户已明确不需要长期保存录音。

### 4.3 上下文邻接【不可逆】

捕捉时如实记录这条消息**前后的事实上下文**：在一个时间窗口内（建议前后 30 分钟，可配置），同一窗口里投递的材料和其他捕捉记录的编号，以及它们与本条之间的时间差。这是日后推断"这个想法被什么触发"的唯一原始依据，**事后无法补录**。

### 4.4 派生结果（可逆，可以重算）

- **触发提议**：这条想法可能与刚投递的哪份材料有关。只作为"提议"保存，附判断来源和置信度，等待用户在回顾中确认。**不得当作已确认的关系。**
- **碎片聚合**：时间上相邻、内容一脉相承的几条碎片，聚合成一个"念头"。聚合可以自动执行，但必须能拆开；聚合结果单独存放，**永不合并或改写原始碎片**。
- 附言（`annotation`）挂到对应的材料上。

### 4.5 写入 Obsidian

> 2026-09-29 更新：存放格式以[决策0003](../decisions/0003-material-foundation.md)为准，即每份素材一个文件，存放在 `素材/YYYY/MM/`，按段落切分、标注实体。下文中"每天一个文件"的建议作废，其余不可逆要求继续有效。

- 在 vault 中新建一个个人区（例如 `我/随手记/`），由应用单向写入。建议每天一个文件，只追加不修改。每条记录带稳定的块编号（例如 `^cap-<捕捉编号>`）和时间，正文就是原话。
- **【不可逆】应用永不修改或删除该区已写入的内容**，遵守现有的 no-clobber 原则。转写订正以追加的"订正"条目表示，不回改原条目。
- 文件内的链接和引用使用编号，不依赖标题或名字匹配。
- 目录名和文件格式可以按工程习惯调整（可逆），但以后改动必须提供迁移。

## 5. 不在本需求范围内

概念锚点、回顾 / 回应生成、taste 归纳、即时对话式深挖、主题页和新知页的改版。已定稿的 UI 和交互未经用户同意不得修改；如果需要新增 Local Web 的待办展示，沿用现有的疑点卡和待办样式。

## 6. 验收

- 测试使用独立、可丢弃的数据目录，不用私人数据库或 Vault（遵守 AGENTS.md）。
- 至少覆盖以下场景：
  - 纯文字想法；
  - 语音想法，包括转写中出现疑点、用户订正的情况；
  - 先投链接，再发语音附言或想法（验证邻接记录和触发提议）；
  - 两分钟内连发三条碎片（验证自动聚合，以及拆开后原始碎片不变）；
  - 大段粘贴的第三方文本（不得进入个人层）；
  - 身份拿不准的短文本（进入待办）；
  - 关闭云端判断开关时的行为；
  - 重复投递和应用重启后不重复落档。
- 交付时说明：哪些不可逆要求是如何保证的（附对应测试），以及做了哪些可逆的取舍。真实飞书设备上的收发验证与合成测试分开报告，不能以合成测试冒充真机结果。

### 可逆取舍

- **识别范围**：不含链接、没有 @ 同题的文字消息和语音算随手记；含链接的消息和图片仍按原有材料投递处理。
- **规则**：
  - 语音默认本人，置信度 1.0。
  - 300 字以上、多段加 120 字以上、带两处以上 Markdown 格式，或出现"转自、来源:、作者:"等标记，判为第三方。
  - 紧跟在一次投递之后（窗口内）、80 字以内、含"这篇、重点看、后半"等指代的，判为附言，对象是最近一次投递。
- **云端判断**：
  - 可替换的 `CloudIdentityJudge`，用当前配置的模型连接。
  - 设置页"随手记云端判断"默认关闭；关闭时不向任何模型发送随手记，语音也不做模型审阅（因而没有模型标出的疑点）。
  - 门槛：本人 ≥0.9，第三方与附言 ≥0.8，否则待定。
- **回执**：随手记在飞书只回一张"已记录 / 原话已保存。"卡片，不追问、不推送疑点卡。语音下载失败时显示"可重试下载"。
- **邻接写入 raw**：
  - 随手记在更早的投递有了 raw 编号之后再写入，最多等 24 小时；仍未定的数量写在"邻接未定"。
  - 素材写入时只列当时已有编号的更早随手记（随手记编号在捕捉时预留，所以待定的也能列出）。
- **编号**：
  - 随手记在捕捉时预留编号，日期取接收日。
  - 判为第三方的随手记，其素材 raw 沿用这个编号和接收时间；若同样文字早已作为素材存在，预留号会空出。
- **待办卡**：沿用首页"需处理"卡的外框、序号与按钮样式。版式按用户 2026-09-30 的设计分左中右三栏：左侧序号；中间自上而下是判断点（身份待定说明）、完整原话（保留换行，不截断）、来源与时间；右侧按钮竖排，依次为"我的想法 / 第三方内容 / 附言"（附言只在前面有投递时出现）。汇总行增加"N 条随手记待定身份"。
- **限制**：语音随手记不能改判为第三方。页面只对"待定"提供选择；已写入后的改判目前仅有后端能力，已测试。
