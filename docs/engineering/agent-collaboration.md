# Agent 需求讨论、归档与开发交接

状态：自 2026-10-01 起作为后续版本的协作约定。它把用户认可的“先讨论、再归档、后施工”方式做成 Claude、Codex 或其他开发 Agent 都能使用的中立流程；不追求工具界面完全相同。

## 核心原则

对话用于澄清和决策，仓库用于跨会话、跨 Agent 的长期记忆。任何 Agent 都不能把自己的聊天记录、自动记忆或“我上次知道”当成最新项目基线。开发开始前必须读实际 Git 状态和仓库中的现行文档。

`AGENTS.md` 只保存长期稳定的工作纪律、数据边界和项目级规则。某一版本的功能、方案、验收和未决项写进对应的 roadmap、decision、product、engineering 或 release 文档，不把一次性任务不断堆进 `AGENTS.md`。

项目继续区分四类事实：

- 用户已经决定的产品要求；
- Agent 提出的建议或方案；
- 代码、测试和正式环境证明的当前能力；
- 仍待决定或尚未验证的事项。

归档时必须标清身份和日期，不能把建议写成用户决定，也不能把计划写成已经交付。

## 两阶段协作

### 一、需求讨论与施工包

需求可以在 Claude Work、Codex 的独立讨论任务或 Plan 模式中沟通。讨论过程中持续更新仓库，不等到最后凭聊天记忆补写。大版本的施工包至少包括：

1. 目标与非目标；
2. 当前基线、目标平台和受影响入口；
3. 用户裁决、设计依据和不可改变的边界；
4. 推荐方案、备选方案及取舍理由；
5. 数据迁移、兼容、失败恢复和隐私边界；
6. 分阶段交付物、逐项验收标准与验证方式；
7. 已知问题、待决事项和必须由用户判断的节点。

优先复用现有文档结构：产品长期规则进 `docs/product/`，架构与运行规则进 `docs/engineering/`，不可轻易改变的裁决进 `docs/decisions/`，版本施工包进 `docs/roadmap/`。不要为了每轮对话再造一套平行权威。

讨论完成的门槛不是“聊天说得差不多”，而是上述内容已写入唯一权威文档，关键分叉已由用户决定，文档改动已提交 Git，并记录作为开发起点的分支与提交。仍未决定但不阻塞的事项可以保留，必须明确其不进入本轮施工。

### 二、开发、验证与交付

开发 Agent 打开同一项目后，先读根 `AGENTS.md`、`docs/README.md`、本次施工包及其直接引用，再核对分支、HEAD、未提交改动和最新远端状态。不能只凭一句“开始工作”猜测范围；“开始工作”的含义是按仓库中已冻结的施工包执行。

大版本或会与其他工作并行的任务优先使用独立分支或 worktree；小修复可在用户指定的当前工作区进行。开发 Agent 按里程碑更新状态，完成实现、相关测试、真实使用路径验证和必要文档，不把明显关联工作留给下一位 Agent。

交付记录至少写明：

- 实际起点和最终提交；
- 实现了什么、没有实现什么；
- 变更文件和重要取舍；
- 测试、构建、人工验收及其对象和结果；
- 是否接触正式数据、正式应用或外部服务；
- 已知限制、未验证项、恢复或回退方式；
- 下一位 Agent 可以从哪里继续。

## Claude 与 Codex 之间怎样交接

两边共享的不是某个账号里的记忆，而是同一工作树、Git 历史和施工包。交接方在停手前提交或明确列出未提交改动，写清当前里程碑和验证结果；接手方先从 Git 与文件反查，再使用聊天导出作辅助证据。聊天导出不能覆盖实际源码、用户最新裁决或正式环境状态。

Claude Code 可以读取 `CLAUDE.md`，Codex 会读取适用范围内的 `AGENTS.md`。两份入口若同时存在，应互相指向同一套正文，不维护两套相互漂移的规则。产品需求和验收仍放在普通项目文档里，使任何 Agent 都能读取。

Codex 中可以用独立讨论任务或 Plan 模式承担“先把需求聊清楚”的阶段，再新建或转入同项目的开发任务。长期、多轮执行可以在开发任务中设置 Goal，但 Goal 只属于该任务，不是项目全局记忆，也不能代替仓库文档。

## 轻量任务的简化

小 bug 不必机械创建完整的大版本施工包。至少要在现有待办或缺陷记录中写清复现、期望、边界和验收，然后由开发 Agent 在正确基线做最小修复、验证并更新状态。只要会跨 Agent、跨天或影响正式数据，就恢复完整交接要求。

## 开发启动语

施工包已经提交后，可以用下面的短指令启动任一开发 Agent：

> 读取本仓库适用的 Agent 规则、文档入口和本版本施工包；核对 Git 基线与未提交改动。按施工包逐项实现和验证，持续更新交付状态；遇到会改变产品方向、不可逆数据边界或外部承诺的缺失决定时，把证据和选项交给我决定，其余必要工作继续完成。

这段话只是入口。真正的范围、约束和完成标准始终以仓库里已经确认的施工包为准。
