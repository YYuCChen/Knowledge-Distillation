# 存储与保留规则

代码、产品意图、私人数据、发行包、临时输出分别管理。

## 长期价值

保留现行代码和适用测试、明确状态的用户决定与未来探索、必要产品/工程规范、简短发行验收证据和独有用户材料。未跟踪文档可能很重要；尚未实现的构想不是缓存。

私人数据、对话、设备配置和凭据留在公开仓库之外。同磁盘副本只能抵御部分误改，不是灾难恢复；重要私人文档需要用户明确选择的可信备份。

## 任务收尾

每项构建/测试使用一个明确临时目录。验收完成且没有活跃引用后，清理可重建环境、中间应用、重复模型、下载分片和无用解压副本；适当只读共享有版本记录的模型资源，不每轮复制。

保留小体积结果、最小复现夹具和未决问题，成功结束的测试不默认永久保留整库和媒体现场。

## 混合历史资料

删除前列出未跟踪/修改文件、未来意图、唯一原文和恢复点；将有价值内容对应到保全目的地并验证，再按精确授权范围删除。不能按年龄或发布版本清空整个工程或废纸篓。

保留必要发行资产和兼容恢复策略，不保留每个历史包。旧应用ZIP不能被宣传为新数据库格式的可靠回退。

## 交付记录

记录新增临时空间、清理结果、剩余内容和理由。目录体积与卷可用空间分开测量，硬链接、写时复制和快照可能导致差异。移入废纸篓不等于释放空间。

这是任务收尾规则，不表示存在无人值守的定时删除服务。
