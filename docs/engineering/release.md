# 发布与构建来源

源码提交、产品版本、构建号、Release标签和文件哈希是不同标识，应分别记录，不从共同的V1.1名称推断对应关系。

核对时公开V1.1使用标签`v2026.09.11.8`、构建`2026.09.11.16`。保留已有下载/升级兼容性，本说明不授权移动标签或替换资产。当前公开源码不保证复现现有二进制的每个字节。

后续发行应记录实际源码提交、平台/架构、依赖锁、构建工具、命令及配置模板、产物哈希、验签、测试结果和限制。若构建包含未提交变更，先解决来源可追溯性，再宣称可复现。

Mac与Windows分别进行原生验证。双平台流程使用 `scripts/dual_build.py` 派发原生构建，V1.2 已完成双平台冻结成品与签名差量验收；本机配置独立存放，不能整包迁入私人电脑工作区。

签名私钥留在受控本地密钥存储。公共验证密钥和feed URL可入库；设备路径、SSH资料、凭据、浏览器状态和私人数据库不能进入源码或安装包。

完整包和差量放Releases，不放源码Git。保留第三方声明与许可；模型权重遵守自身再分发条件并记录固定来源。本页不是新增许可专项审计。

更新必须验证真实性和适用基线。同一不可信站点提供的哈希不能单独证明发布者。产品要求用户明确选择整包时，差量失败不得悄悄下载完整包。

应用回退与数据/schema回退是两件事，不能因为留了旧ZIP就用旧程序打开新数据。保留现用数据，在隔离副本验证失败恢复。

发布后同步README的当前版本、下载地址、平台范围和实际能力；不要因打包任务改写用户认可的README整体结构。

## 发行附件大小门禁

Windows完整ZIP严格小于2,000,000,000字节；全部附件严格小于2,147,483,648字节。数值唯一配置为 `packaging/release_policy.json`。打包后与上传前执行 `scripts/check_release_sizes.py <全部实际附件> --report <验收文件>`，检查真实大小及剩余额度，等于上限即失败。禁止删除必要功能、依赖、许可或改为隐含联网/分卷安装来缩包。
