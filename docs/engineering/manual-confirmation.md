# 人工判断身份与迁移

2026-09-15用户裁决：相似疑点只显示第一张普通疑点卡，保留已发布V1.2的布局、文案、按钮与展开交互；一次判断通过整组原子事务同步全部相似位置。旧分组卡、位置列表和部分勾选要求已被替代；底层仍保留版本检查、逐成员审计和幂等机制。定稿UI的后续改动须事先征得用户同意。

另一页面完成判断后，含本地草稿或正在播放原音的普通卡保留原DOM节点，草稿只读可复制，提交失效；最后一张待处理卡消失也不能删除其草稿容器。本页成功提交的卡片正常移除。此为已批准的草稿保留行为，不改变正常疑点卡设计。

V1.3按审核轮次、疑点成员、判断组和入队次序分别记录身份。`concern_uid`不占用媒体`member_id`；`review_round_id`不沿用会随状态变化的`review_revision`。音频资源和纯文本偏移变化不改变判断身份；候选、来源或决定依据变化使判断版本失效。

schema 19在原pending JSON之外增加`manual_cards`与`group_decisions`。schema 18迁移只建立稳定兼容映射，保留原JSON和未知字段；首次业务写入增补v2字段。旧卡按单成员读入；缺可证明人工入队时间时按投递时间、任务编号、原疑点序推定，缺失时间排在有效时间之后，逐卡标明推定及原因。读取不分配新身份，迁移失败整笔回滚。

新增组进入本作用域队尾，同轮暂停再返回保留原序；新审核轮次不继承旧优先级。集合保持独立作用域。公开后的组不能静默增加成员，部分处理剩余成员继续使用原队列位置。组决定在现有SQLite事务中检查整份pending和全组判断版本（包括未选成员），将pending、来源事实、队列与逐成员决定账本共同提交。相同请求或相同版本/选择重放一次生效，异payload拒绝。

升级接受前失败由安装快照恢复旧库；接受后不得以旧数据库覆盖新数据。旧二进制不能直接打开新schema，代码回退须使用兼容新schema的修正版。上述数据库机制的合成测试不代替分组语义、客户端体验或原生安装旅程验收。
