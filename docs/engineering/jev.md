# Jev：封闭判断交给 TypeSafe Jev

Jev 是 TypeSafe 的"系统一"模型：只回答选择题（choice）、打分题（score）和是非题（noul），返回校准过的概率，不写文字（[API 参考](https://docs.typesafe.ai/api)）。应用只把"从已知选项里选"的工作交给它，要写文字的工作仍由 LLM 完成。

## 用户裁决（2026-09-30）

- 划定由 Jev 承担的工作，只要 Jev 已配置就优先走 Jev，用户不需要手动开关。
- Jev 没有配置时，各项工作走原来的方案。
- Jev 已配置但调用出错时，要把错误报出来，当作缺陷修复；不能悄悄改用 LLM，也不能猜一个结果。
- 设置页"模型配置"里 Jev 只占一行：API Key 和"保存并启用"。不展示"由 Jev 承担的工作"。
- 路径管理里原先的"随手记云端判断"开关取消。
- 语音随手记不再做 LLM 审阅：内容是用户自己说的，发出前自己会检查。

## 由 Jev 承担的工作

| 工作 | 配置了 Jev | 没配置 Jev | 实现 |
|---|---|---|---|
| 随手记身份判断 | 规则判不了的交给 Jev，问一道四选一（本人 / 第三方 / 附言 / 拿不准）。本人要 ≥0.9，第三方和附言要 ≥0.8；把握不足的进待处理 | 只用规则，判不了的进待处理 | `v1/captures.py` 的 `JevIdentityJudge` |
| 整理时的历史召回 | 每个候选（历史素材、已接受新知、现有关系、待重审关系）问一道是非题，全部放在同一次请求里；"值得展开"的概率 ≥0.5 才入选，输出格式与原来相同 | 原来的 LLM 召回 | `v1/jev_recall.py` |

出错时的表现：

- **身份判断**：记为待定，依据写"Jev 失败·错误码"，写入错误日志；首页卡片显示出错原因，由用户手动判断。
- **历史召回**：本次整理失败，首页显示"本次知识整理未完成"，写入错误日志。
- **Key 失效**：设置页 Jev 一行变为"不可用"，换一个 Key 后恢复。
- **429 / 529**：按文档退避重试两次，仍失败就按上面各项的方式处理。

**Key 的保存**：点"保存并启用"时，先用一道很小的题向 Jev 核对这个 Key，通过后才存进本机的应用密钥目录，页面上不会回显。Key 被拒绝和连不上 Jev 时，给出不同的提示。

**隐私**：配置 Jev 之后，随手记原文和整理时的素材摘要会发给 TypeSafe。不想外发，就不配置 Jev。

## 应用里哪些 LLM 工作可以交给 Jev（2026-09-30 评估）

| 工作 | 结论 |
|---|---|
| 随手记身份判断 | 已交给 Jev |
| 整理时的历史召回 | 已交给 Jev |
| 主题归类 | 部分可以：归入已有主题是选择题，新主题的命名和范围说明需要写文字。拆分后再评估 |
| 图片识别疑点复核 | 判断部分可以，但替换文字和逐字依据需要 LLM，拆开收益小 |
| 知识提炼、语音转写审阅与候选改法、生成新知、等价疑点合组、知识与新知的呈现修复、抖音合集综合 | 都要写文字或逐字引用原文，不能交给 Jev |

## 兼容性实测（2026-09-30，用户的 Key，全部为合成素材）

**身份判断**：20 条中文消息。

- 全部调用成功，模型版本 jev-1.13.0；返回格式与文档一致，全部通过严格校验。
- 耗时中位 0.53 秒，最长 0.66 秒。
- 意思明确的 16 条里，15 条自动判对；剩下 1 条附言把握只有 0.64，进了待处理。
- 4 条模糊消息里，3 条进了待处理；"明天再说"以 0.91 判为本人。它确实是用户自己的话，只是没有实质内容，整理时守则会跳过。
- 没有把他人内容判成本人，也没有把本人判成他人。
- 用错误的 Key 调用时返回 401，应用得到 `jev_unauthorized`。

**历史召回**：1 份新材料对 10 个候选。

- 10 个全部判对：相关的都在 0.8 以上，无关的都在 0.4 以下。
- 用时 0.59 秒，输入 2364 token，输出 176 token。
