# 知识蒸馏器 · Knowledge Distiller

**让读过的内容，成为下一次思考的起点。**

[快速了解](#快速了解) · [深入了解这个项目](#深入了解这个项目)

## 快速了解

- 收藏一篇文章、记下一段观点之后，还能从中想到什么？知识蒸馏器从这个问题出发，希望让值得留下的材料，在回看、联系与判断中，带来新的认识。
- AI 帮你读材料、理清观点和依据、发现可能的联系；你来核查、取舍，留下自己的想法。这里积累的不只是内容，还有你如何理解它们。
- 项目当前围绕个人阅读与知识整理展开：先把来源读清楚，再把不同材料联系起来，让已有积累继续启发思考。

[下载应用](https://github.com/YYuCChen/Knowledge-Distillation/releases/latest) · [版本记录](https://github.com/YYuCChen/Knowledge-Distillation/releases) · [反馈问题](https://github.com/YYuCChen/Knowledge-Distillation/issues)

### 现在可以做什么

- **把材料留下来**：提交支持的链接、文本或文档，恢复可读原文，提炼观点、论证和对应证据，保存来源型笔记到自己的 Obsidian。
- **把内容读明白**：从观点回到依据和上下文；影响理解的听写、文字识别疑点，会交给你核对。
- **把积累联系起来**：主动点击「开始整理」，组织主题、梳理已有知识的关系，在有依据时提出新知候选。
- **留下自己的认识**：对新知选择「有点意思」或「再想想」，记录批注，以后也可以追加想法、改变判断。
- **需要时找回来**：通过主题浏览和本地文字搜索回顾材料。当前搜索用于查找已有内容，不生成问答。

作者原本的表达、AI 推导出的新知、你的个人判断，始终分开记录。新知是继续思考的邀请，不是替你下的结论；材料不足以支持新联系时，也可以不生成。

### 支持哪些材料

- **平台链接**：抖音、小红书、知乎、微博、X、YouTube、B 站中已支持的内容类型。具体获取受登录、权限和平台限制影响，并非任意页面都能处理；视频主要处理讲述内容，不分析画面。
- **文本与文档**：直接粘贴正文，或提交单个 PDF、EPUB、UTF-8 Markdown 文件；不递归导入整个目录或 Vault。
- **飞书投递**：配置自己的机器人后，可在已绑定私聊中发送链接和文字。电脑需要开机且应用运行；V1.1 支持已接入的图片、图文投递与确认；不支持任意文件或音频附件。

### 下载与开始使用

- **当前公开版：V1.1**（构建 `2026.09.11.8`）。以下说明以已发布版本为准，具体更新见版本记录。
- **Mac**：[下载 Apple Silicon 安装包](https://github.com/YYuCChen/Knowledge-Distillation/releases/download/v2026.09.11.8/KnowledgeDistiller-2026.09.11.8-macOS-arm64.zip)，约 1.56GB，要求 macOS 14+。解压后将应用放入「应用程序」再打开；不支持 Intel Mac。
- **Windows**：[下载 x64 安装包](https://github.com/YYuCChen/Knowledge-Distillation/releases/download/v2026.09.11.8/KnowledgeDistiller-2026.09.11.8-Windows-x64.zip)，约 1.89GB。全部解压到可写文件夹，运行 `KnowledgeDistiller.exe`；不要只复制 EXE。已验证 Windows 10 22H2，Windows 11 与 ARM64 尚未验证。
- **首次安全提示**：Mac 当前未公证，Windows 未作发行者代码签名。请核对下载来源，按系统提示处理，不关闭整体安全防护；Mac 可参考 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。GitHub 的 `Source code` 压缩包不是应用安装包。
- **首次配置**：在设置中选择已在 Obsidian 打开过的 Vault，配置模型连接，再用一段短文本试一次蒸馏。按所用功能准备 Chrome、Codex、Obsidian 及自己的账号，无需另搭 Python 环境。
- **按需启用**：处理有声内容前配置语音识别，可选本地 Qwen 或云端豆包；Qwen 需主动下载安装并保存启用。内容平台连接、飞书机器人按需配置。

应用启动后在浏览器中使用，可在设置中自定义本地访问名称和固定端口。Windows 服务窗口需保持运行；只关闭网页不会退出后台。

V1.1 优化了长内容疑点核对与保存速度、候选解释布局、飞书图片和图文确认处理，以及 Mac 更新说明与包大小展示。两端离线 OCR、PDF、EPUB 样本已检查，PDF 结构识别可能不同；Windows SSH 环境下 B 站超时清理可能延迟，普通桌面场景仍待验证。

### 数据、费用与更新

- **本地保存**：应用记录保存在本机 SQLite；Obsidian 保存来源型笔记。AI 新知和相关个人判断当前保留在应用内，不自动写入 Obsidian，也不做双向同步。
- **本地优先不等于全离线**：已有内容浏览与搜索在本机完成；获取网络材料、使用云模型或飞书需要联网。云端处理会将任务所需材料交给对应服务，账号、额度及费用由你自行管理。
- **备份两处**：同时备份应用数据与 Vault。Mac 数据位于 `~/Library/Application Support/Knowledge Distiller/`，Windows 位于 `%LOCALAPPDATA%\Knowledge Distiller`；凭据迁移可能需要重新配置。
- **升级先看说明**：Mac 可在设置中检查并下载更新，当前发行仍需手动替换完整包，不承诺自动安装；Windows 使用下载完整 ZIP 的手动更新方式。更新前等待任务结束、退出旧服务并备份，不删除数据或 Vault，不同时运行两个版本，不用旧版打开新版数据。

### 关于项目

- 从个人使用需求出发，持续打磨来源质量、阅读、整理与桌面体验；当前不提供团队协作、跨设备自动同步或通用知识库聊天。
- 此仓库用于介绍、发行与反馈，应用源码目前私有。第三方组件、模型与资源遵循各自许可，请保留随包声明。
- 欢迎在 [Issues](https://github.com/YYuCChen/Knowledge-Distillation/issues) 留下使用场景与问题，附上版本、系统和复现步骤；请先移除密钥、Cookie、私人材料等敏感信息。

## 深入了解这个项目

### 从收藏之后的问题开始

一段视频把问题说得很透，一篇文章让人突然有了思路，于是先收藏起来。但过了一阵子，可能只记得“看过一个相关说法”：出处找不到了，成立的条件忘了，当时受到的启发也没留下。即使存了一段摘要，真正想用它时，还是需要重新理解一遍。

知识蒸馏器就是从这样的个人使用需求开始的。它希望接住的，不只是那条链接，还有一次阅读之后尚未展开的思考：作者究竟在说什么？为什么这样说？它和以前看过的材料有什么关系？放回自己的经验里，又会带来什么不同的理解？

因此，这个项目的着眼点不止是把资料存得更多、检索得更快。那些能力是基础；更关心的是，积累能否重新参与到阅读和思考中。AI 在这里帮助恢复材料、整理依据、提出联系，让人有机会接着往下想。是否认同、哪里存疑、哪些东西值得带进自己的生活，仍然需要使用者自己的回应。

### 先让一份材料站得住，再让知识联系起来

项目早期围绕来源恢复、转写与提炼展开。很快就遇到一些不能只靠“生成得流畅”解决的问题：一个关键词听错，可能改变整段话的意思；一个结论摘掉前提，就可能不再是作者的观点；一段看起来完整的摘要，也可能掩盖来源缺失。

这些问题逐渐形成了现在的处理方式：先尽可能读清材料，再提炼观点；结论保留对应证据，重要疑点交给使用者核对。来源无法可靠取得时，应说明哪里出了问题，而不是把推测补成原文。保存的也不只是一段简短总结，还有以后可以核查的上下文。

接下来，工作从“处理好一份材料”延伸到“怎样持有和使用一批知识”。来源型笔记进入 Obsidian，主题与搜索帮助回找；当积累里出现可以相互补充、对照或解释的内容时，主动整理再尝试提出新的联系。

这也带来了另一个重要区分：作者说过什么、AI 从中推导了什么、使用者如何看待它，不能混成同一种知识。现在的新知候选会等待人的判断，可以觉得有意思，也可以暂时搁置。后来想法发生变化，仍能继续追加，而不是把过去的理解悄悄抹去。

### 在真实使用中，逐步变成桌面工具

随着处理对象从简单文本扩展到视频、图文和文档，工作重点也从单次生成转向了完整使用过程：分享链接里夹着口令怎么办，平台登录失效怎么办，识别疑点如何定位，处理失败后哪些步骤能够继续，保存成功的笔记又怎样顺畅打开。

飞书投递让手机上遇到的内容有了入口，应用中的待办承接必要核对，Obsidian 则承接来源型笔记的深读。围绕这些连接，项目持续调整页面排版、信息层次和操作反馈，希望使用者把精力花在材料上，而不是猜测程序正在做什么。

到了桌面发行阶段，挑战又变成了另一些具体问题：别人能否完整解压并启动，依赖是否齐备，升级是否保留数据，失败后能否恢复。V1.0 开始提供 Mac 与 Windows 安装包，V1.1 进一步统一了两端源码与构建版本，并完成两端冻结应用、离线文档样本和归档校验。两个平台的识别结果、验证范围和更新方式仍有差异；构建成功、实际可用和正式发布，需要分别确认。

整个过程是在个人使用、产品讨论、AI 辅助开发与实际验收之间反复推进的。功能先能运行，再放进真实材料与日常操作里检验；一些看似很小的阅读、确认和恢复细节，往往就在这个过程中成为下一轮工作的重点。

### 技术如何支撑这些取舍

应用采用本地服务与浏览器界面的组合。Python 承担处理流程，Flask、Jinja 和前端页面提供交互；打开桌面应用后，浏览器连接的是本机服务。这样既能使用熟悉的网页交互，也能让任务与正式数据留在自己的电脑上管理。

SQLite 和 Obsidian 承担不同的职责。SQLite 保存来源身份、处理记录、知识关系、新知以及个人判断等结构化记录；Obsidian 中的 Markdown 用于阅读和长期持有来源型内容。前者记录应用里的完整关系，后者让材料可以独立打开。这也是为什么只复制笔记不能恢复全部应用状态，以及当前没有把 Obsidian 当作双向同步数据库。

材料处理按类型分工。文档链使用 Docling 等组件恢复正文与结构；平台图片文字在 Mac 上使用 Apple Vision，在 Windows 上使用 PaddleOCR。语音识别可选择云端豆包，或选装本地 Qwen3-ASR：Mac 使用 MLX 路径，Windows 当前使用 Transformers CPU 路径。LLM 再对明确取得的内容进行提炼与整理。解析、识别与推导分开处理，有助于保留来源定位，也让疑点不至于被流畅的生成结果掩盖。

本地优先并不意味着每一步都离线。网页材料仍需从平台取得，选择云模型时，任务所需内容也会发送给相应服务。哪些数据留在本机、哪些步骤要联网，应当能够解释清楚，而不是由一个“本地应用”的标签替代说明。

发行包通过 PyInstaller 等工具携带基础运行依赖与文档资源，因此体积比一个轻量网页入口大。本地 Qwen 的组件与权重则按需安装。Mac 的更新链路使用 Sparkle 与更新签名验证，Windows 当前仍是手动更新；签名校验、系统授权和实际升级成功是不同层面的事情，不能因为接入了更新组件就承诺所有设备都能无感升级。

这些能力建立在 Python、Flask、SQLite、Obsidian、Docling、Qwen、MLX、PyInstaller、Sparkle、FFmpeg、OpenCLI 等项目与工具之上。相关代码、模型和资源遵循各自许可；列举技术组成不代表官方合作或背书。

### 接下来，沿着什么方向继续

近期仍然以日常使用是否可靠为重心：打磨来源连接、疑点核对、阅读与恢复体验，完善 Mac 和 Windows 的构建、安装与更新验证。具体交付以发行说明为准，不把内部候选构建当作用户已经拿到的功能。

更远一些，有几个问题值得继续探索。围绕一个明确目的持续阅读多份材料时，能否形成比零散笔记更有用的成果？随着知识增加，主题的组织怎样既便于回顾，又能容纳理解的变化？一个人的认识如何逐渐形成、被补充或被修正，又适合怎样呈现？

另一个有意思的方向，是让自己的表达与已有知识发生联系。日常突然冒出的灵感、想说的一段话，也许可以成为探索的起点：借助以前读过的内容，把当下的感受想得更清楚。这需要保留“自己的表达”和“外部材料”的区别，也不能把一次随口表达直接当成稳定立场，更不能让 AI 的解释冒充本人的意思。

这些目前都是待讨论、待验证的方向，不是已经实现的能力，也没有确定的交付日期。要不要做、以什么形式做，仍然取决于它是否真的帮助理解和思考，而不是能否再增加一个功能入口。

项目会继续从这些具体的问题里往前走：让认真选择的材料留下依据，让不同的认识有机会相遇，也给使用者留出形成自己看法的空间。
